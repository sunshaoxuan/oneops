製品構築 操作マニュアル

ビルド端末の状態を確認し、製品種別と交付内容に合う構成 Parameter を入力して、構築、Log 確認、交付 Package の Download まで進める手順です。

この手順でできること構築 Task の開始から交付成果物の取得まで
操作の流れ
  1. 利用前の確認
  2. 端末を確認する
  3. 構造種別を選ぶ
  4. Parameter を入力する
  5. 構築を開始する
  6. 進行と Log を見る
  7. 成果物を取得する
  8. 履歴と設定を管理する
  9. 失敗時の確認
01

利用前の確認

画面入口
左メニュー「製品構築」
必要権限
builder.use
Browser 接続先
OneOps HTTPS 同一 Origin
  • 画面、API、履歴、Log、成果物は OneOps Gateway 経由です。Browser から旧 8091 やビルド端末 Port へ直接接続しません。
  • 共通 Context で組織機関を選択済みの場合、顧客機関名へ名称が初期設定されます。今回の交付対象に合わせて編集できます。
  • 埋め込み画面では言語選択と製品 Navigation は OneOps 側に統合され、構築 Workspace 内へ重複表示されません。
  • 待機中または実行中 Task がある間、構成 Form は Locked されます。
02

ビルド端末を確認する

  1. 画面上部の「状態更新」を押す

    端末状態、CPU、空き Memory、空き Disk を取得します。端末が稼働中の場合は Branch と資材番号候補も読込まれます。

  2. 状態表示を確認する

    構築開始には端末が「稼働中」である必要があります。「停止中」は管理された通常状態で、OneOps 全体の障害を意味しません。

  3. 停止中なら「ビルド端末を起動」を押す

    起動要求後は状態が切り替わるまで状態更新で確認します。稼働中になると構築 Form を利用できます。

  4. 停止する場合は確認文字を入力する

    ビルド端末を停止は誤操作防止の確認を要求します。実行中 Task がないことを確認して操作します。

状態意味次の操作
running / 稼働中端末へ接続でき、構築情報を取得できます。Parameter 入力へ進みます。
stopped / 停止中端末は設定済みで停止しています。必要な場合だけ起動します。
unreachable端末へ到達できません。Network、VM、Host 設定を確認します。
permission_deniedVM 制御権限がありません。運用管理者へ連絡します。
unknown状態取得が完了していません。状態更新を再実行します。
03

製品版と構造種別を選ぶ

  1. 新しい入力を始める場合は「新規構造」を押す

    履歴閲覧 Mode から新規入力 Mode へ戻り、Form を初期状態にします。

  2. 「製品バージョン」を選ぶ

    通常の One人事交付は「標準版」、NHO 向け固有交付は「NHO版」を選びます。選択に応じて表示項目と資材候補が切り替わります。

  3. 標準版では「標準版構造種別」を選ぶ

    「機関封包」「標準発版」「顧客化」から今回の成果物を選びます。

構造種別使う場面画面上の特徴
機関封包特定顧客機関へ正式交付する一式を生成顧客機関名、事前準備、導入計画を入力します。
標準発版共通標準版の成果物を生成顧客機関名は「共通」として送信されます。
顧客化選択した構成要素だけを再生成Backend、Frontend、Help、conf_prod、SQL、Data Sync、導入計画、Runtime を Checkbox で選びます。
NHO版NHO 版資材を使用した交付NHO 用 Branch と資材番号候補を使用します。
顧客化の構成要素不要な要素を解除すると関連 Form 区画も非表示になります。今回の交付範囲を確認してから構築してください。

05

構築を開始する

  1. 端末が稼働中であることを再確認する

    停止中の場合、画面は構築開始を拒否します。状態更新後に進みます。

  2. 資材と Branch を照合する

    資材番号、Backend Branch、Frontend Branch、必要に応じて Help SVN Revision が交付指示と一致することを確認します。

  3. 対象機関と構造種別を照合する

    顧客機関名、標準版または NHO 版、機関封包、標準発版 または顧客化の選択を確認します。

  4. Host と接続 Parameter を照合する

    AP Host IP、DB Host、Port、WEB Host、HTTPS、Mail、UPDS など今回使用する接続値を確認します。

  5. 同梱する構成要素を照合する

    Help、conf_prod、SQL、Data Sync、導入計画、Runtime、Middleware と Object Storage の選択を確認します。

  6. 機密値の入力先を確認する

    Password や接続資格情報を必要な Field だけへ入力し、構築 Log や Task 名へ転記しません。

  7. 「構造を開始」を押す

    OneOps CSRF Header とともに Task 作成要求が送られます。成功すると構造履歴へ新規 Task が追加され、選択状態になります。

  8. Form が Locked されたことを確認する

    Task が queued または running の間は入力変更と重複開始が無効になります。停止が必要な場合は停止を使用します。

顧客機関名の履歴Task には開始時の機関名が保存されます。後で共通 Context を切り替えても、過去 Task の機関名は上書きされません。
06

構造履歴、工程、Log を確認する

queued→running→success / failed / cancelled
  1. 「構造履歴」から実行中 Task を選ぶ

    Active Task は自動選択され、状態、機関名、開始時刻などが表示されます。

  2. 「成果物」で工程を確認する

    各 Step は pending、running、success、failed、cancelled の Icon と状態で表示されます。Remote Build、Download、SQL、Package などの現在位置を確認します。

  3. 「実行ログ」の末尾を確認する

    実行中は Offset を保持して Log を追記取得します。端末待機中は Heartbeat と Remote Status が更新されます。

  4. 中止が必要なら「停止」を押す

    Task の Cancel API を呼び出します。終了後は cancelled として履歴へ残り、構築 Form が再度利用可能になります。

  • queuedHost Worker が Task を受け付け、実行開始を待っています。
  • running端末 Build、資材取得、交付 Package 生成などを実行中です。
  • success選択した全工程が完了しました。
  • failed工程のいずれかで終了しました。結果と Log の最終 Error を確認します。
  • cancelled利用者の停止要求により終了しました。
07

交付 Package を作成して取得する

  1. 成功した Task を履歴から選ぶ

    結果領域の交付パッケージに生成状態、ファイル名、期限が表示されます。

  2. 未生成なら「生成してダウンロード」を押す

    選択 Task の成果物から正式交付 ZIP を作成し、完了後に Browser Download を開始します。

  3. 生成済みなら「ダウンロード」を押す

    保存 Dialog のファイル名を確認して取得します。

  4. 期限切れなら「再生成してダウンロード」を押す

    保持期限が切れた Download Package を現在の Task 成果物から再生成します。

  5. 取得後に成果物を照合する

    対象機関、製品版、資材番号、選択構成、ファイル名を交付記録と照合します。

08

構成設定履歴と Task 履歴を管理する

  1. 保存済み構成を再利用する

    構成設定履歴から対象設定を選ぶと Form へ値が復元されます。顧客、版、資材の現行値を確認してから開始します。

  2. 過去 Task の事実を確認する

    構造履歴で Task を選び、開始時 Parameter、工程、Log、交付 Package を確認します。

  3. 不要な設定履歴を削除する

    設定履歴の削除操作を使用します。今後の再利用対象から外れます。

  4. 不要な終了 Task を削除する

    queued または running ではない Task だけ削除できます。必要な Log と成果物を保存してから操作します。

履歴削除前の確認Task 履歴は構築 Parameter と結果の運用証跡です。正式交付に使った Task は監査と再現に必要な期間を確認してから削除してください。
09

構築できない、失敗したときの確認順

  • Form が操作できないqueued または running Task がないか確認します。履歴の Active Task を完了または停止します。
  • 構築開始できない端末が running か、必須項目が入力済みか、顧客化の構成要素が一つ以上あるか確認します。
  • Branch 候補が空端末状態を更新し、running になってから候補を再取得します。
  • MinIO / RustFS が切り替わる同じ S3 互換用途のため相互排他です。今回使用する一方だけを選びます。
  • Task が failed結果の最初の failed Step と Log の最終 Error を確認し、資材、SVN / Git、Remote Build、Disk 容量を切り分けます。
  • Download できないPackage の available / expired 状態を確認し、期限切れなら再 Package 化します。
  • API Error が構造化表示される画面の Message と Code、Task ID、発生時刻を記録して管理者へ連絡します。
  • 端末停止で 502 になる現行契約では停止は HTTP 200 の正常状態です。Gateway と Worker の Version、状態 API 経路を管理者へ確認します。
