# 项目强规则

更新时间：2026-07-24

## 档案主键与引用

所有档案和业务记录必须具有独立、稳定且不向普通画面展示的物理 ID。

业务代码用于用户识别、检索和业务唯一性约束。业务名称及其他字段用于表达业务信息。跨档案的强关联必须保存被引用档案的物理 ID，并由数据库外键约束保证引用完整性。

禁止用可修改的业务代码或名称承担档案和业务记录间的强关联外键。该规则适用于本系统现有及以后新增的全部档案和业务记录。

组织机构的区分属于系统档案。组织机构只能通过 `classification_id` 物理外键引用区分档案，不得将区分名称作为组织机构表中的自由文本保存。

## 工程根目录

`D:\nginx` 是本系统的工程根目录。系统源码、配置、运行时、依赖、日志与启动入口必须能够从该目录解析。OneOps 复用 EnvPortal 已部署的 Windows 域认证结果，不复用 EnvPortal 的用户角色、权限或业务数据。

## 用户、身份与权限

OneOps 必须维护独立的用户、外部身份、会话、角色、权限、角色授权、用户角色分配和审计记录。域认证代理只提交经过签名的域身份断言，不承担用户档案和权限管理。

认证与授权相关记录遵守物理 ID 规则。后端 API 是权限判定的最终边界。密码、会话令牌、CSRF Token、SSO 票据和共享密钥禁止写入日志或审计详情。

详细需求见 `D:\nginx\docs\AUTHENTICATION_AND_RBAC_REQUIREMENTS.md`。

系统管理的信息架构必须区分基本档案与身份访问管理。组织区分、产品和版本归入基本档案管理；用户、角色权限和认证审计归入独立的用户管理分组，并通过细分二级菜单进入。

系统管理的一级菜单和页面大标题必须使用相同名称，避免使用“管理”等缩略入口名称。

已登录用户必须能够从右上角账号菜单进入个人资料并修改自己的显示名。个人资料中的用户名和电子邮件只读。用户手工保存的显示名优先于后续 Windows SSO 目录同步，并记录个人资料更新审计。

左侧品牌区的 OneHR 标志、产品名和多语言副标题必须保持稳定布局。副标题在桌面侧栏和移动抽屉中均使用单行显示，不允许因可用宽度不足发生折行。

环境台账功能在菜单和页面标题中使用完整名称。日文统一为“環境情報”，中文统一为“环境信息”，英文统一为“Environment information”。

共通上下文的组织机构选择器必须同时支持机构编码和机构名称的包含查询。匹配时统一大小写和全角半角字符，选择完成后继续显示机构名称。

OneOps 通过 OHR0067 上既有的 EnvPortal 域认证代理取得 EnvPortal 短期身份令牌。OneOps 服务端向 EnvPortal 验证令牌并读取用户档案，随后在 OneOps 自有数据库中建立外部身份、会话和默认 `VIEWER` 角色。EnvPortal 角色和权限不得传入 OneOps。

源码、配置、数据库迁移、脚本或需求文档发生变化时，本机持续交付任务应立即执行完整测试、生产构建和发布验证。测试失败时保留当前发布版本。持续交付高权限任务的监视目录必须限制普通用户写入。
