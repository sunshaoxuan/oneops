# AI 応答 Markdown 表示調査

## 調査対象

- 右下の浮動 AI アシスタント
- 第 1 階層の全画面 AI アシスタント
- 問合支援の AI 補助分析、根拠、保存済み返信案

## 原因

`AiAssistantChat.tsx` は AI 応答を通常の `div` のテキストノードへ直接配置し、CSS の `white-space: pre-wrap` だけで改行を表現していた。このため、CAG が返した Markdown の表、見出し、リスト、コードは構造化されず、記号を含む原文のまま表示されていた。

問合支援の AI 補助も、分析項目と履歴返信案を通常のリスト項目または `Paragraph` へ配置しており、同じ表示制約があった。

## 実装

1. 共通 `AiMarkdown` コンポーネントを追加した。
2. CommonMark と GitHub Flavored Markdown の表、取り消し線、タスクリスト、自動リンクを有効化した。
3. 浮動表示と全画面表示で共通する `AiAssistantChat` の AI 応答へ適用した。
4. 問合支援の問題分析、根拠、保存済み返信案へ適用した。
5. 生 HTML を無効化し、外部画像は取得せず代替テキストだけを表示するようにした。
6. 外部リンクへ `noopener noreferrer` を設定した。
7. 表を固定レイアウトにし、利用可能な横幅へ収めて各セル内を自動改行するようにした。
8. CAG と Model API の指示から内部項目名を除外し、保存済み応答に残る `questionKey` も `Q5` などの業務表示へ変換した。
9. AI アシスタントの問合せ参照へ「問合せを開く」操作を追加し、検索を実行せずチケット詳細と参照質問を復元するようにした。

## 幅問題の追加調査

初回実装では表へ `min-width: max-content` を設定していたため、全画面 AI アシスタントで長い四列表が会話領域を超えていた。ブラウザー画面の横スクロールが発生したことを確認し、表を `table-layout: fixed`、`min-width: 0` へ変更した。セルへ `overflow-wrap: anywhere` と `word-break: break-word` を設定した。

最終ブラウザー検証では次を確認した。

- 文書幅 1,128 px、文書スクロール幅 1,128 px
- 全画面の表とラッパー幅 387 px
- 浮動表示の表とラッパー幅 347 px
- ブラウザー警告とエラー 0 件

## 問合せ参照の追加検証

全画面 AI アシスタントの「参照済み · No. 94056 · Q5」から開く操作を実行し、問合支援へ遷移した。検索条件と検索結果を経由せず No. 94056 の詳細ドロワーを取得し、Q5 が展開されたことを確認した。浮動 AI アシスタントは同じ会話と参照を維持した。ブラウザー実行ログは 0 件だった。

## 変更境界

CAG のコード、設定、プロセスは変更していない。OneOps の表示、OneOps から CAG へ渡す指示、問合せ詳細の復元処理を変更した。
