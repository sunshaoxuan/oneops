# 环境产品识别与凭据能力修正调查

## 调查目标

确认 EnvPortal 的应用、数据库与 RDP 凭据为何没有进入 OneOps，并修正 UHR、UPDS、PHR 的产品识别与版数规则。

## 根因

1. EnvPortal `data.csv` 保存应用登录 ID、登录密码、数据库用户名和数据库密码。
2. EnvPortal `rdp.csv` 保存 RDP 用户名、RDP 密码和连接地址。
3. 旧导入器主动删除凭据字段，只在暂存行记录字段数量。
4. 环境详情只显示端点地址，没有端点维护与凭据操作。
5. 旧导入器把环境名 `UHR` 硬编码映射为产品 Code `01`，由此错误关联 UPDS V6。

## 修正结论

1. `U-PDS人事給与` 保持一个 UPDS 主档，沿用既有物理 ID 与 V6、V7。
2. U-HR 归入独立产品 `U-PDS給与明細`，使用模块范围版数规则。
3. 同一环境中，同一稳定模块只允许一个版数，不同模块可以使用不同版数。
4. PHR 归入独立产品 `庶務事務システム`，版数为 1.0、1.1、1.5，使用单版数规则。
5. 4 个 UHR 环境改为 U-HR 产品候选，等待按模块确认实际版数。
6. 应用、数据库和已匹配 RDP 凭据进入端点凭据表，使用 AES-256-GCM 加密。
7. 运维人员可以新增和编辑连接端点，显式查看、复制与保存用户名和密码。
8. 凭据查看与修改记录审计事件，普通环境接口、暂存行和导入报告只返回登记状态与字段数量。

## 未匹配边界

1. “标准版”环境没有 OneOps 组织机构，继续保留在暂存区。
2. 两条社内 RDP 记录缺少可确认的组织与环境归属，继续保留在暂存区。
3. VPN 资料分析与候选审核仍属于后续功能。
