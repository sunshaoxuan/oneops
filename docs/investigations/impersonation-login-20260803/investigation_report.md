# 代理ログイン実装調査記録

更新日: 2026-08-03
対象バージョン: OneOps 0.7.2

## 調査結果

ヘッダーにはログアウトの独立ボタンがあり、利用者表示はプロフィールダイアログを直接開く構造でした。認証セッションは `auth_sessions.user_id` で権限対象を決め、`auth_audit_events` は実行者と対象を記録できます。ユーザー管理には既存の利用者一覧と操作列があるため、代理ログイン操作を同じ列へ追加しました。

## 採用した構造

`auth_sessions.impersonator_user_id` を追加し、`user_id` を対象利用者、`impersonator_user_id` を代理実行者として保存します。セッション解決後の権限計算は `user_id` だけを使用するため、代理中は対象利用者の権限境界になります。代理終了時は対象セッションを失効させ、実行者の通常セッションを発行します。

## 制約

代理開始は `identity.users.impersonate` 権限、CSRF、実行者の有効状態を要求します。自己指定、多重代理、無効利用者を拒否します。開始・終了・失敗を操作監査へ記録し、セッション値と CSRF 値は記録しません。
