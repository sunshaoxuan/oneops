# 権限マトリクス用語及び横幅 調査報告

## 目的

ロール編集画面の権限マトリクスで、API の原文キーが英語として露出する問題、同じ操作の大文字小文字違いによる重複列、横方向の余分なスクロール、顧客情報と組織機関の用語関係を整理する。

## 調査結果

1. Migration 034 の顧客ナレッジ権限は資源 `CUSTOMER_KNOWLEDGE` と操作 `USE`、`REVIEW`、`MANAGE` を保存していた。Portal の旧実装は小文字の操作だけを辞書化していたため、原文キーがフォールバック表示されていた。
2. 権限マトリクスは資源と操作を表示用の小文字キーへ正規化し、`CUSTOMER_KNOWLEDGE` を `customer.knowledge` として既存の顧客ナレッジ行へ統合する。
3. `organizations` は顧客情報画面ではなく組織機関の基本台帳である。顧客情報は選択中の組織機関を強参照する業務ビューであり、顧客ナレッジの操作対象も組織機関物理 ID である。
4. 顧客ナレッジの入口と API は現行要件どおりシステム管理に置く。マトリクス上では関係を理解できるよう「顧客情報 > 顧客ナレッジ管理」と表示する。
5. 操作列は「閲覧、編集、利用、確認、管理、代理ログイン」とし、既存の保存用 Code は変更しない。操作説明を画面内に表示し、閲覧、編集、利用の境界を明示する。

## 実装範囲

- `permission-matrix.ts` に資源及び操作の正規化と安定順序を追加した。
- `IdentityManagementPage.tsx` に顧客ナレッジの三言語名称、操作の三言語名称及び操作説明を追加した。
- 操作列幅を 128px から 112px へ変更し、資源列の長い機能パスは折返し可能にした。
- 権限マトリクスの単体試験と UI の静的契約試験を追加・更新した。

## 制約

権限 API の保存契約、権限 Code、顧客ナレッジのシステム管理入口及び対象組織機関物理 ID は変更していない。実データは認証済み管理者の正式画面で確認した。

## 2026-08-10 追加調査及び修正

Migration 037 は `inquiries.deleted.read` を資源 `inquiries.deleted`、操作 `read` として登録する。この権限は、問合支援の AI 補助履歴を論理削除後もシステム管理者が参照するために使用される。Portal の資源名辞書及び権限名辞書にこの資源が登録されていなかったため、対象行だけ API の資源キー `inquiries.deleted` がそのまま表示されていた。

今回、`inquiries.deleted` を `inquiries` の直後へ安定配置し、資源名と `inquiries.deleted.read` の権限名を日本語、中国語、英語へ追加した。保存する Permission Code と認可判定は変更していない。

Portal の専用試験と本番ビルドは成功した。静的 Portal は Gateway を再起動せずに配信し、Nginx 設定検査及び HTTPS 入口の応答を確認した。全量 `pnpm check` は、今回の変更範囲外で並行作業中のモデル設定バリデーションに対する既存テストが一件失敗したため、正式リリース判定へ使用していない。認証済み管理者の実画面へ進める Browser セッションはなく、権限行の DOM、Console、スクリーンショットは `evidence_missing` とする。
