# 問合せ全体 AI 補助の配置と分析範囲調査

## 目的

問合せ詳細の電球操作と「AI補助」の役割を分離し、画面上の配置と Model API へ渡す分析意図を一致させる。

## 調査結果

変更前は顧客質問、サポート発言、問題ブロック末尾の三か所が、それぞれ `QUESTION`、`MESSAGE`、`NEXT_REPLY` として同じ問題ブロック内に保存されていた。「AI補助」も `NEXT_REPLY` のため、画面上も Prompt 上も一つの問題ブロックを主対象としていた。

要件上の役割は次の二層に分かれる。

1. 顧客質問とサポート発言の電球は、選択位置を主対象とする。
2. 「AI補助」は問合せ全体を主対象とし、問題ブロックに所属しない。

## 実装判断

新しい `TICKET` アンカーを追加した。既存の実行 API とデータ構造を維持するため、最新問題ブロックの `questionKey` を保存先の識別に利用する。Prompt ではこの値を主分析対象として扱わず、全問題ブロックと顧客評価を案件全体の主証拠として扱う。

画面では問合せ全体の操作、実行パネル、履歴を問題ブロック一覧の下、顧客評価の前へ配置した。既存の `NEXT_REPLY` 履歴は元の問題ブロック末尾へ読み取り専用で残し、新しい実行入口は削除した。

## 影響範囲

1. API クライアントのアンカー型
2. Gateway の入力検証
3. Model API Prompt
4. AI 補助履歴の配置解決
5. 問合せ詳細ドロワーの UI とスタイル
6. PostgreSQL のアンカー制約
7. 要件、変更履歴、バージョン

## セキュリティ

問合せ全体の分析でも既存の連絡先、秘密情報の除外処理を通す。添付本文は Model API へ送信せず、添付ファイル名と形式だけを参照情報に含める。

## 同一リリース内の AI助手 UI 修正

浮動ウィンドウの最小化と閉じるは、どちらも `setOpen(false)` だけを実行していた。状態、履歴、添付、Session の扱いに差がないため、重複する最小化操作と文言を削除し、閉じる操作へ統一した。

クイックナビゲーションでは、スクロール位置から更新する選択状態を波形の中心にも使用していたため、波形が常時表示されていた。クリック選択を保持する `activeNavigationId` と、ホバーまたはキーボードフォーカス中だけ設定する `hoveredNavigationId` を分離した。会話本文のスクロール監視を削除し、静止時は選択済みの黒い長線とその他の短線だけを表示する。

AI助手の浮動ウィンドウは `z-index: 1600` である一方、内部 Tooltip と確認ポップアップは Ant Design の既定層を使用していたため、ポータルがウィンドウ背面へ隠れていた。AI助手内の全ポップアップを `1700` へ統一し、右端の問合せを開く Tooltip は左方向へ展開するようにした。

## 問合せ全体分析モード

`TICKET` アンカーは全問題ブロックを Prompt へ渡していたが、出力形式は質問単位の `UNANSWERED` または `REPLIED` と共通だった。そのため、画面上の範囲は問合せ全体でも、結果は選択した質問の要点、調査方向、現在回答の充足度を中心としていた。

`TICKET` アンカーをサーバー側で `FULL_TICKET` へ固定した。出力契約は次の 5 領域とする。

1. 各回の顧客質問と顧客公開回答の対応度
2. 各回の見落とし、再質問、最初の顧客公開回答までの待ち時間
3. 顧客評価と対応記録の関係
4. 全体のサービス品質、リスク、条件付き最終結論
5. 必要な是正対応

内部記録は判断根拠に含め、顧客へ届けた実回答には数えない。待ち時間は記録時刻から Gateway が分単位で計算する。最後の問題ブロックに顧客公開回答が存在する場合だけ最終結論を必須とし、存在しない場合は `null` を強制する。`FULL_TICKET` では返信案を生成しない。

## マイグレーション再実行への対応

Gateway は起動時にすべての SQL マイグレーションを順番に再実行する。旧 `018_add_inquiry_assist_anchor.sql` が `TICKET` を含まない制約を再作成していたため、既存の `TICKET` 履歴がある環境では `021` の拡張前に起動が停止した。旧マイグレーション側の再作成制約にも `TICKET` を追加し、全履歴を保持したまま反復実行できるようにした。Gateway の停止、失敗原因の再現、修正後の Scheduled Task 起動、内部と公開 HTTPS の健康確認を実施した。
