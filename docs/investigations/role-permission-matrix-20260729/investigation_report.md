# ロール権限マトリクス調査・実装報告

## 結論

従来のロール編集画面は、権限 Code と名称を二列のチェックボックス一覧として表示していたため、機能ノードと操作種別の対応を比較しにくい構造でした。

権限 API が返す `resource` と `action` を利用し、機能ノードを行、操作種別を列とする権限マトリクスへ変更しました。各交点には業務名称と安定した権限 Code を併記し、権限が存在しない交点は `－` で表示します。

## 実装範囲

1. `resource` 単位で権限を集約する純粋関数を追加しました。
2. 操作列は `read`、`write`、`use` の順序とし、未知の操作も決定的な順序で追加します。
3. 機能ノードは業務利用順で表示し、未知のノードは末尾へ安定して追加します。
4. ロール編集モーダルを権限マトリクス表示へ変更しました。
5. 日本語、中国語、英語のノード名称、操作名称、説明文を追加しました。
6. 変更要件を `docs/PROJECT_RULES.md` へ追記しました。

## 検証上の制約

正式な HTTPS 画面とリリース済みアセットは確認しました。ブラウザー環境では旧 HTTP の Windows ドメイン認証入口が `ERR_BLOCKED_BY_CLIENT` で遮断されたため、認証後の画面検証は同じ最終ビルドと実際の API 契約を使用するローカル受入フィクスチャで実施しました。

ローカル受入ではマトリクス表示、既存選択値、チェック解除と復元、コンソールを確認しました。実ユーザーによる本番ログイン後の再確認は未実施です。
