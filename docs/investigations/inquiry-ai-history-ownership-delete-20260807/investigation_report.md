# 問合 AI 補助履歴の生成者と論理削除 実装記録

## 目的

問合支援の AI 補助履歴へ生成者を表示し、生成者本人による論理削除と、システム管理者による削除済み履歴の省スペース参照を実現する。

## 調査結果

`inquiry_assist_runs.requested_by_user_id` には生成要求時の認証ユーザー物理 ID が既に保存されていた。履歴 API はこの ID と利用者名を返しておらず、履歴の削除状態、削除 API、削除済み参照権限も存在しなかった。

## 実装契約

1. 既存の `requested_by_user_id` を生成者の安定参照として使用する。
2. 利用者表示名は `users` を物理 ID で結合して取得する。
3. 論理削除は `deleted_at` と `deleted_by_user_id` を保存する。
4. 削除 API は認証ユーザーと生成者の物理 ID が一致する場合だけ成功させる。
5. 通常の履歴一覧、単一履歴及びイベント参照から削除済み履歴を除外する。
6. `inquiries.deleted.read` を持つシステム管理者だけが `includeDeleted=true` を使用できる。
7. 削除済み履歴は本文を展開せず、省略記号 Icon と最小限の監査情報だけを一行で表示する。
8. 削除操作は `INQUIRY_AI_RUN_DELETED` と `SOFT_DELETE` で操作監査へ記録する。

## 検証状態

単体試験、TypeScript、本番 Build、Spring Backend 試験、実 PostgreSQL、公開環境、Browser、Console、Screenshot はすべて合格した。

実 Browser の初回検証では、浮動確認が Drawer の表示領域外へ配置される不具合を検出した。確認 UI を履歴 Card 内の固定確認条へ変更し、完全な最終受入を先頭から再実行した。修正版では生成者表示、本人削除、管理者向け削除済み一行表示を確認した。

受入専用履歴は検証後に物理削除し、残留件数 0 を確認した。公開証跡は AI 履歴領域だけを裁切し、顧客情報、問合本文及び問合 Header を含めていない。
