# 問合支援 AI 辅助状态分流调查报告

## 调查目标

本次调查确认同一套 AI 辅助入口如何根据当前客户问题的回复状态改变分析目标，并验证重点回复操作的上下文范围。

## 状态判定

系统在调用 Provider 前确定分析模式，模型不能自行改变模式。

1. `UNANSWERED`
   当前问题块不存在 `INTERNAL_DISCUSSION` 或 `CUSTOMER_VISIBLE_REPLY`。
2. `REPLIED`
   当前问题块至少存在一条内部讨论或客户可见回复。
3. `SYSTEM_EVENT` 与 `ATTACHMENT_EVENT` 不计作回复。

## 输入与输出约束

### 未回复问题

分析输出必须包含问题要点、调查方向、缺失信息、风险和确认事项。现有证据不足时，`draftReadiness` 为 `NEEDS_INVESTIGATION`，服务端清空模型返回的草案。现有证据可以支持可靠结论时，才允许生成使用礼貌客户用语的回复草案。

### 已有回复

分析范围保留当前客户问题与该问题块内全部支持记录。输出增加回复整体评价、缺失观点、风险、建议回复结构和客户回复草案。

从消息右上角灯泡启动时，系统仍保留问题块完整上下文，并把选中回复写入重点上下文。`focusedReplyAssessment` 单独评价该回复与客户问题的匹配性、缺失内容、措辞风险和客户影响。

## 运行时防线

1. Provider 输出的 `mode` 必须等于系统判定值。
2. 所有分析字段必须符合结构要求。
3. 未回复且仍需调查时，服务端强制返回空草案。
4. 已有回复场景必须返回客户用语草案。
5. Provider 失败保持原 Provider，不执行自动切换。
6. 运行事件和审计详情记录分析模式，辅助任务记录 Token 用量。

## 真实页面验证

1. 已回复样本从客户可见回复的灯泡启动，页面显示“返信内容の分析”和“選択した返信を重点評価”。
2. 已回复样本返回问题要点、调查方向、回复整体评价、重点回复评价、缺失观点、风险、回复结构与草案，Token 总量为 2914。
3. 未回复样本从问题块底部启动，页面显示“未回答の質問分析”。
4. 未回复样本因证据不足显示“調査後に返信”，回复视图没有草案文本框，Token 总量为 1937。
5. 已回复草案包含真实换行，不含字面量 `\n`。
6. 浏览器控制台没有错误或警告记录。

真实验证只在人工点击 AI 入口后创建辅助任务。保留的截图已经裁去工单号、标题、客户、负责人和正文。
