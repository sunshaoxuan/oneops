# ワークベンチ構築履歴復旧調査

## 事象

Spring Boot への API 移行後、ワークベンチの「最近の構築タスク」が空表示になりました。

## 確認結果

構築履歴の実データは残っています。本機の `app/builder-data/standalone-builds` に 14 件の `metadata.json` があり、全件が成功状態でした。構築端末 `192.168.250.50:8090` の `/api/builds` も 14 件を返しました。

Spring の `WorkbenchController` は製品構築データを参照せず、`tasks` と全てのタスク集計を固定の空値として返していました。この仮実装が空表示の直接原因です。

## 修正

- `GET /api/work-center/v1/dashboard` を、実データから生成される製品構築スナップショットへ再接続しました。
- `GET /api/work-center/v1/events` も同じ互換サービスへ接続し、継続更新契約を復旧しました。
- 製品構築の読み取りモデルを Spring へ完全移行するまで、固定空値による仮実装を禁止する設計規則を追記しました。

## 結論

本事象はデータ削除ではなく、Spring API の読み取り経路欠落です。修正後は既存の 14 件をワークベンチへ再表示できます。
