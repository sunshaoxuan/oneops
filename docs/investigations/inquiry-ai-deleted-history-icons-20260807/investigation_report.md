# 削除済み問合 AI 補助履歴の管理者表示 実装記録

## 1. 目的

削除済み AI 補助履歴が一件ごとに大きい空 Card を占有し、削除前の内容を確認できない画面を修正する。通常利用者には削除済み履歴を表示せず、管理者には小さい Icon の一覧を示し、選択時に削除前の詳細を確認できる状態とする。

## 2. 原因

`AssistHistoryAtAnchor` が削除済み履歴も通常履歴と同じ内側 `Collapse` の項目へ変換していた。項目自体は `collapsible=disabled` であり、通常 Card の枠、余白及び高さを使用しながら詳細を開く操作を持たなかった。

## 3. 実装

- 履歴を有効履歴と削除済み履歴へ分離した。
- 削除済み履歴を高さ 34 px の一つの領域へまとめ、一件につき 30 px の Icon として表示した。
- Hover 時に生成者及び削除日時を Tooltip へ表示した。
- Icon 選択時に読み取り専用 Modal を開き、削除日時、質問位置、Provider、Model、生成者、作成日時、完了日時、状態、Token、解析結果及び保存済み返信案を既存詳細 Component で表示するようにした。
- 削除済み詳細では再削除操作を表示しないようにした。
- 通常利用者へ削除済み履歴を返さない API 権限制御は既存契約を継続した。

## 4. 検証結果

Portal、Gateway、Worker、Spring の関連試験及び正式 Build は合格した。Version 0.15.8 を正式 Runtime へ公開し、HTTPS Portal の Asset と 8092 Health を確認した。

管理者の実データ三件で、三つの Icon、Tooltip、詳細 Modal、元の解析内容及び再削除 Button 非表示を確認した。対象三件には保存済み返信案が存在しなかったため、返信案の実データ表示は共通詳細 Component と Source 試験で確認した。Browser Console の error 及び warning は 0 件であった。

## 5. 結論

削除済み履歴は管理者画面で小さい Icon の一覧となり、画面占有を抑えながら削除前の保持内容へ到達できる。通常利用者の非表示境界は API 権限で維持される。
