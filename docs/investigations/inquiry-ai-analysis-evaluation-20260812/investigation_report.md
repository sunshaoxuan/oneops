# 問合支援 AI 分析評価 調査及び実装報告

## 目的

問合支援で生成した AI 分析へ利用者が好評又は差評を登録し、差評理由、提案及び評価を分析履歴と結び付けて永続化する。保存資料は将来の教師あり学習及び品質監督のレビュー候補として利用できる状態にする。

## 現行経路の確認

問合支援の AI 分析実行は `inquiry_assist_runs`、進行イベントは `inquiry_assist_run_events` に保存される。分析実行には票番号、分析位置、Provider、Model、生成者物理 ID、分析結果、Token 使用量及び完了状態が記録される。通用 AI 会話の保存経路とは分離されている。

## 実装契約

`inquiry_assist_run_evaluations` を追加し、評価 ID、分析実行物理 ID、評価者物理 ID、評価値、自由記述、作成日時及び更新日時を保存する。評価値は `POSITIVE` 又は `NEGATIVE` とし、自由記述は 2000 文字以内とする。分析実行と評価者の組合せを一意にし、再操作は同一評価を更新する。

API は認証済み利用者 ID を評価者として使用する。完了済みで論理削除されていない分析だけを受け付ける。履歴取得時は現在利用者自身の評価だけを返す。評価登録及び更新は `INQUIRY_AI_RUN_EVALUATED` として操作監査へ保存する。

Portal は現在表示中の分析と保存済み履歴の双方へ共通評価部品を表示する。好評は押下時に保存し、差評は理由入力欄を展開して保存する。失敗及び削除済み履歴には評価操作を表示しない。

## 調査した成熟パターン

公開されている LLM 評価基盤では、評価を特定 Run へ結合し、Score、Comment、評価元及び評価者を記録する形式が採用されている。本実装も同じ追跡単位を採用し、OneOps 内部の物理 ID、認証及び監査契約へ統合した。

## 学習資料としての境界

評価は分析入力、出力、Model、実行履歴と結合できるレビュー候補である。評価単体を教師データの正解として自動採用しない。学習用抽出、匿名化、承認、Dataset 化及び外部提供は別管理手順の対象とする。
