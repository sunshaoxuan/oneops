## 交付限制

三件のテンプレートを保存し、すべて有効にした。`0220 一橋大学` では 23 件の課題を共通列へ表示し、`ONEHR OneHR株式会社` では一致課題なしを確認した。実データでは同一課題が複数テンプレートへ一致するケースは確認できなかったが、ID をキーとする重複排除は単体テストで確認した。

ユーザー名、パスワード、API Key の値は記録していない。Backlog 公式仕様に従い、通常の `/api/v2/projects` が返す参加済みプロジェクトと、管理者向け `all=true` の全プロジェクト取得を別の権限確認として扱う。今回の `all=true` は 403 であったが、目標プロジェクトの利用及びテンプレート保存には影響しなかった。

今回のソート変更では完全なローリング配信が Nginx reload 段階で Windows `Access is denied` を返し、主サービスは 8092 と 8093、upstream は 8092 のまま維持された。その後、プロジェクト配信スクリプトの静的リソース経路で Portal を配信し、認証後画面で既定昇順、降順切替、跨頁連続性及び Console 0 件を確認した。正式ローリング配信の Nginx reload 権限問題は実行環境制限として記録する。
