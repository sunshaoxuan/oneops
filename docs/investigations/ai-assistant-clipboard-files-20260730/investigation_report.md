# AI助手クリップボード添付調査

## 目的

浮動ウィンドウと全画面の AI助手で、画像とファイルをクリップボードから貼り付け、またはドラッグアンドドロップで追加し、CAG の回答根拠として利用できるようにする。

## 調査結果

既存実装には、複数ファイル選択、OneOps へのアップロード、送信前の添付一覧、CAG Task への添付指示、署名 URL、SHA-256、利用者・Conversation・Task の関連付けが存在した。

不足していた箇所は次のとおりである。

1. 入力欄の貼り付け処理が `text/plain` だけを参照し、クリップボード内の画像とファイルを取得していなかった。
2. ドロップ処理が `DataTransfer.files` だけを参照し、ブラウザーが `DataTransfer.items` にだけファイルを公開する場合を扱っていなかった。
3. ドラッグ対象が子要素を通過するたびに離脱判定が発生し、ドロップ領域の強調表示が不安定だった。
4. 画像・ファイルの貼り付けとドラッグアンドドロップが利用できることを画面から把握しにくかった。

## 実装

1. `DataTransfer.files` と file 種別の `DataTransfer.items` を共通関数で正規化した。
2. 同じ転送に両方の表現が含まれる場合は件数を考慮して重複を除外し、同名・同サイズの別ファイルは維持した。
3. 貼り付け時は画像・ファイルを優先し、ファイルがない場合だけ既存の大容量テキスト変換を実行する。
4. ドラッグ深度を管理し、子要素間の移動で強調表示が消えないようにした。
5. 浮動ウィンドウと全画面の入力欄に貼り付け・ドラッグ操作の案内を追加した。

## CAG 連携

OneOps Gateway は添付を `runtime/ai-assistant-uploads` に保存し、利用者、Conversation、CAG Task と関連付ける。CAG Task の Prompt には、署名付き内部ダウンロード URL、ファイル名、MIME type、サイズ、SHA-256 と取得指示が含まれる。

実行環境では OneOps Gateway が `127.0.0.1:8092`、CAG が同一 Windows ホストの `0.0.0.0:8000` で稼働している。CAG の実行プロセスから内部署名 URL を利用できる構成である。CAG のコードとプロセスは変更していない。

## 実機確認

1. 全画面 AI助手でクリップボード PNG を貼り付け、`clipboard.png` の添付表示を確認した。
2. 問合支援上の浮動ウィンドウで同じ操作を行い、同じ添付表示を確認した。
3. ファイル選択で PNG 2 件を同時に追加し、個別削除操作を確認した。
4. 赤枠内に `questionKey` と表示された画像を貼り付けて CAG に送信し、CAG が `questionKey` と回答した。
5. 2 件の実送信添付で SHA-256 が保存され、CAG Task への関連付けが完了していることを確認した。
6. ブラウザーコンソールは 0 件だった。

## 残存事項

ブラウザー自動操作は OS ファイルを画面外からドラッグする操作を提供しないため、実ブラウザーでのドラッグ投入は自動化していない。ファイル転送の判定、`files` と `items` の正規化、重複除外、ドラッグ深度は単体テストで確認した。ファイル選択、クリップボード貼り付け、CAG 実送信は実ブラウザーで確認した。
