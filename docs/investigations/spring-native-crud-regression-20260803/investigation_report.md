# Spring ネイティブ CRUD 回帰調査記録

更新日: 2026-08-03
対象バージョン: OneOps 0.8.1

## 現象

ロール・権限画面で VIEWER の権限を変更して保存すると、画面下部へ `The operation could not be completed.` が表示され、保存できなかった。

## 原因

Spring のロール更新 SQL は UUID のロール物理 ID を Java の `String` としてバインドしていた。正式 PostgreSQL で同じ処理を自動ロールバック付きで実行した結果、`operator does not exist: uuid = character varying` を再現した。

さらに、従来の `saveRole` は要求された `permissionCodes` を検証、削除、追加しておらず、ロール本体だけを更新して空の権限配列を返していた。このため UUID エラーを回避しても権限変更は保存されない実装だった。

同じ移行コードを調査したところ、利用者更新は UUID、基本台帳と環境台帳は BIGINT の物理 ID を文字列として渡していた。正式 PostgreSQL CRUD テストにより、組織更新 SQL が存在しない `organizations.updated_at` を参照する問題も検出した。

## 修正

1. ロール物理 ID を UUID として検証し、ロール本体と `role_permissions` を同一トランザクションで保存するようにした。
2. 権限コードを小文字化、重複除去し、存在しない権限が含まれる場合は関連更新前に拒否するようにした。
3. 利用者 ID とロール ID を UUID、組織・製品・版数・モジュール・環境・接続先 ID を BIGINT としてバインドするようにした。
4. 組織更新 SQL から存在しない `updated_at` 更新を除去した。
5. Spring の変更 API へ `requireMutationPermission` を適用し、権限確認後に CSRF を検証するようにした。
6. 権限不足を 403、CSRF 不正を 403 として識別し、予期しない内部エラーはサーバーログへスタックトレースを記録するようにした。

## CRUD テスト範囲

| 領域 | 実行内容 | データ保護 |
| --- | --- | --- |
| ロール・権限 | 一覧、作成、更新、権限関連置換、重複除去、不明権限拒否、UUID 検証、CSRF 拒否 | Spring トランザクションで自動ロールバック |
| 利用者 | 状態更新、ロール割当置換、セッション失効 SQL | Spring トランザクションで自動ロールバック |
| 基本台帳 | 組織区分、組織、製品、版数、機能モジュールの作成、読取、更新 | Spring トランザクションで自動ロールバック |
| 環境台帳 | グループ、環境、製品関連、接続先、認証情報、アーカイブ、復元、一覧 | Spring トランザクションで自動ロールバック |

ロール削除 API は現行契約と画面に存在せず、利用者割当との参照整合性を含む削除要件も定義されていないため、今回の CRUD テスト対象に含めていない。

## データ確認

テスト終了後に `CRUD_%` と `ENV_CRUD_%` のテスト用ロール、組織区分、組織、製品が 0 件であることを確認した。正式データはロール 3 件、ロール権限 39 件、利用者 12 件、利用者ロール割当 12 件、組織 106 件、環境 4 件、製品 12 件を維持している。
