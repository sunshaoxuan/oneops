# AI助手画像貼り付けとプレビュー調査

## 調査対象

AI助手の全画面と浮動ウィンドウにおいて、クリップボード画像が 1 回の貼り付けで 2 件追加される事象と、画像添付の表示及び拡大確認操作を対象とした。

## 原因

1. クリップボード画像はブラウザーから `DataTransfer.files` と `DataTransfer.items` の両方へ返される場合がある。
2. 従来の同一性判定には `lastModified` が含まれていた。同じ画像でも取得経路ごとに `lastModified` が異なる場合があり、別ファイルとして扱われていた。
3. 添付待機列の判定は React の描画時点の状態を参照していた。連続した貼り付けイベントが状態反映前に到着すると、双方が同じ画像を追加できた。
4. 初回の縮小画像実装は一時 URL を状態初期化時に作成した。React の開発時厳格検査で検査用の解除処理が先行し、縮小画像が表示できないことをブラウザー検証で確認した。
5. Ant Design 6 の Modal コンテナーは `.ant-modal-container` であり、旧構造を対象としたスタイルは適用されなかった。また `maskClosable` は廃止予定 API の警告を出力した。

## 実装

1. 1 回の転送内ではファイル名、サイズ、Content-Type を用いて `files` と `items` を統合した。
2. 画像のアップロード待機列に同期 Ref を設け、状態描画前の連続イベントも同じ判定対象へ含めた。
3. 画像は待機列と送信済みメッセージの双方で縮小画像として表示し、ファイル名は画面上の主要表示から外した。
4. 元のファイル名は縮小画像と削除操作のアクセシビリティ名へ残した。
5. 縮小画像の選択で前景 Modal を開き、閉じる操作と外側マスク領域の選択で閉じるようにした。
6. 一時 URL は Effect ごとに作成と解放を対にし、開発時厳格検査でも有効な URL を再生成するようにした。
7. Modal は Ant Design 6 の `mask={{ closable: true }}` と `.ant-modal-container` を使用した。

## 対象外

CAG のコード、プロセス、会話保存仕様、添付解析仕様は変更していない。
