# 問合支援 多次元検索 調査報告

調査日: 2026-07-30

## 1. 目的

OneHR サポートサイトの UPDS 問合せ検索画面が提供する検索軸を確認し、OneOps の問合支援へ同じ検索能力を安全に組み込む。

## 2. 調査方法

OneOps に保存済みの接続設定を利用し、Gateway と同じログイン処理で検索画面を読み取った。資格情報、Cookie、CSRF Token は出力していない。検索フォーム `id_search_form` の入力名、選択肢の値、階層表示名、送信方式を確認した。

## 3. 実サイトの検索契約

| 検索軸 | 実サイトの入力名 |
| --- | --- |
| キーワード | `k` |
| AND・OR | `kt` |
| 追加質問・回答・コメント | `cr` |
| 問合せ No. | `sbi` |
| ステータス | `s` |
| 作成期間 | `cdc`、`cdb`、`cde` |
| 回答希望期間 | `rdc`、`rdb`、`rde` |
| 更新期間 | `mdc`、`mdb`、`mde` |
| 顧客、顧客名、顧客コード | `cu`、`cun`、`cuc` |
| 担当者、未設定、氏名 | `oc`、`ocno`、`ocn` |
| サブステータス | `ss` |
| カテゴリー | `c` |
| 分類・調査結果 | `it` |
| 質問者名 | `cn` |

カテゴリーと分類・調査結果は hidden input と階層メニューで構成される。メニューの `value` を API 値、`full_name` を画面表示名として利用する。

## 4. 選択肢と実検索の確認

実サイトから担当者 431 件、顧客 260 件、サブステータス 8 件、カテゴリー 500 件、分類・調査結果 10 件を取得した。顧客「京都大学」を指定した読取専用検索では実サイトの全件数が 3,157 件、表示件数が上限の 500 件となり、表示された 500 件の顧客名がすべて指定顧客と一致した。

## 5. 実装判断

基本条件は問合せ No.、キーワード、AND・OR、追加記録対象、ステータス、作成期間、担当者、担当者未設定とした。残りの条件は初期展開された詳細条件へ整理した。

カテゴリーは 500 件の階層メニューを再現せず、完全パスを検索できる単一選択にした。実サイトの値は変更せず Gateway へ送信する。

問合せ No. とキーワードを併用した場合は、実サイトで No. を特定し、取得した詳細へ AND・OR と追加記録対象の条件を適用する。

## 6. 結論

実サイトが提供する検索軸を OneOps の API、Gateway、画面へ対応付けた。既存のステータス制約、AI 対応履歴、結果上限警告、監査コンテキストを維持している。
