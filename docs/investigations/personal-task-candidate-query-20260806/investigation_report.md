# 個人タスク候補検索条件 調査報告

調査日: 2026-08-06

## 1. 調査目的

タスク画面の候補一覧に、現在利用者が担当していない完了済み問合せが 500 件表示される原因を確認する。候補一覧の更新方式、条件変更後の再生成、採用済み候補の再表示制御を確認し、実用可能な検索テンプレートの設計条件を整理する。

## 2. 結論

現在の問合せ接続には `status=open` と `assignee=X02851` が保存されている。外部 UPDS 検索画面で `open` は有効な状態値である。担当者欄は外部担当者の物理的な選択値を要求し、`X02851` は有効な選択値ではない。現在利用者「社内/孫 紹煊」に対応する値は `113210` である。

無効な担当者値を送信した検索は、外部画面で条件付き結果として成立せず、全 75,452 件の先頭 500 件を返した。取得された 500 件はすべて `CLOSED / 回答済`、担当者は `U-PDSサポート` であった。有効な担当者値 `113210` と `open` を指定した読取専用検索結果は 0 件であった。

現行機能には候補検索テンプレートの独立モデルがない。個人接続の `filter_json` に状態と担当者を直接保存している。接続設定の保存後に手動同期または定期同期を実行できる。条件から外れた既存の保留候補を整理する照合処理がないため、条件変更だけでは候補一覧を再生成できない。

## 3. 現行データ

| 項目 | 確認結果 |
| --- | --- |
| 問合せ接続 | `UPDSサポートサイト` |
| 外部ログインユーザー | `X02851` |
| 保存条件 | `status=open`、`assignee=X02851` |
| 同期間隔 | 15 分 |
| 最新同期 | 成功 |
| 候補 | `PENDING` 500 件 |
| 候補状態 | 全件 `CLOSED / 回答済` |
| 候補担当者 | 全件 `U-PDSサポート` |
| 直近の同期 | 各回 500 件を取得し、既存 500 件を更新 |
| 採用済み候補 | 0 件 |

## 4. 原因の処理経路

1. Portal は問合せ担当者を自由入力欄として保存する。
2. 保存済み値は `filter_json.assignee` の `X02851` である。
3. 問合せ接続器は `status`、`assignee`、`assigneeName` を検索条件へ設定する。
4. `assigneeName` の未設定時には外部ログインユーザー `X02851` を担当者氏名として補完する。
5. 問合せ検索 Source は担当者値を `oc`、担当者氏名を `ocn`、状態を `s` へ変換する。
6. 外部検索画面の担当者選択肢は 432 件あり、`X02851` は選択値に存在しない。
7. 外部画面は無効な担当者条件を含む検索で全件一覧を返す。
8. Parser は返却画面を正常な検索結果として処理する。
9. Candidate Repository は外部接続 ID と外部オブジェクト ID で 500 件を追加または更新する。
10. Portal は `PENDING` 候補を表示する。

## 5. 状態条件の追加確認

外部検索画面の状態値は `open`、`close`、`1` から `10` である。Portal は完了状態の値として `closed` を表示し保存するため、完了条件も外部契約と一致していない。OPEN の詳細状態は未回答、回答中、チェック依頼中、チェック済、一次回答済、保留中を選択できる。

## 6. 動的更新の現状

候補データはデータベース上のスナップショットである。Gateway は 1 分ごとに同期対象を走査し、接続ごとの 15 分間隔を満たした時点で外部検索を実行する。画面には候補 API の定期ポーリングが設定されていない。画面操作後の Query invalidation、手動同期、画面再読込または再フォーカスが表示更新の契機となる。

増分取得にも契約不一致がある。問合せ接続器は `modifiedFrom` を作成し、Source は `updatedFrom` を参照する。保存済み Cursor は外部検索の更新日条件へ適用されない。現行同期は毎回同じ 500 件を再取得している。

## 7. 条件変更と再生成

接続条件を保存すると次回同期から新条件が使用される。保存操作自体は同期を開始しない。同期処理は取得された案件の upsert だけを行い、新条件で返されなかった既存 `PENDING` 候補を失効させない。このため、現在の 500 件は担当者条件を修正して 0 件が返った後も候補一覧へ残る。

実用的な再生成には Template Revision と Generation Run を持つ照合処理が必要である。今回の実行で一致した候補を Seen とし、同じ Template に由来する既存候補で Seen にならなかったものを `STALE` または失効状態へ移す。履歴追跡のため物理削除は行わない。

## 8. 採用済み候補の扱い

候補を採用すると Candidate は `ADOPTED` になり、Personal Task と External Link が作成される。以後の upsert は `ADOPTED` を維持するため候補一覧へ再表示されない。External Link の外部状態と外部更新日時は同期時に更新される。

候補を「今回は除外」すると `DISMISSED` になる。外部更新日時が変わった場合だけ `PENDING` へ戻る。外部更新日時の解析または Cursor 適用が不正確な場合、この再表示判断の信頼性も低下する。

## 9. 推奨する検索テンプレート設計

### 9.1 接続とテンプレートの分離

認証情報を持つ External Account と、候補生成条件を持つ Candidate Query Template を別の物理 ID で管理する。一つの接続に複数テンプレートを関連付けられる構造とする。

### 9.2 必須条件

| 条件 | 設計 |
| --- | --- |
| 対象者 | `ME`、`SPECIFIC_ASSIGNEE`、`UNASSIGNED` を明示選択する |
| 担当者 | 外部選択肢の物理値を保存し、表示名は参照表示に使用する |
| 状態 | 初期値を OPEN とし、外部選択肢の実値を保存する |
| 詳細状態 | OPEN の 1 から 7 を複数選択可能にする |
| 更新期間 | 初回取得期間と継続同期 Cursor を分ける |
| 上限 | 外部上限と実件数を表示し、切捨て時は候補生成を不成立にする |
| 有効状態 | Template の有効、無効と Revision を保持する |

### 9.3 任意条件

顧客、顧客 Code、サブステータス、カテゴリー、分類・調査結果、キーワード、回答希望期間、作成期間、更新期間を外部検索契約に合わせて追加する。条件値は外部 Options API から選択し、自由入力による無効値を保存しない。

### 9.4 実行前検証

保存前に条件値の有効性、同一階層の矛盾、検索結果件数、外部表示上限を検証する。Preview は件数、状態分布、担当者分布、先頭数件を表示する。無効な選択値、全件検索への退行、500 件切捨てを保存エラーとして扱う。

### 9.5 再生成と由来管理

`保存` と `保存して再生成` を分ける。再生成は Template Revision を固定して Generation Run を開始し、候補と Template の一致関係を記録する。複数テンプレートに一致する候補は一件へ集約し、由来 Template を複数保持する。

### 9.6 候補の状態

`PENDING`、`ADOPTED`、`DISMISSED` に `STALE` を追加する。`ADOPTED` と External Link は再生成でも保持する。`DISMISSED` は外部更新時だけ再確認する。`PENDING` が新条件から外れた場合は `STALE` へ移す。

## 10. 実装優先順位

1. 担当者を Options 由来の Select へ変更し、`ME` を外部担当者物理値へ解決する。
2. `assigneeName` へのログイン ID 補完を削除する。
3. 状態 `closed` を外部値 `close` へ修正し、詳細状態を外部 Options から扱う。
4. Source 返却時に要求条件と結果の状態、担当者を検証し、条件逸脱時は同期を失敗させる。
5. `modifiedFrom` と `updatedFrom` を統一する。
6. 独立した Candidate Query Template と Generation Run を追加する。
7. 再生成時の Seen 照合と `STALE` 遷移を追加する。
8. 画面へ最終同期時刻、Template Revision、取得件数、切捨て、再生成操作を表示する。

## 11. 調査範囲

本調査はソースコード、現行データベース、外部 UPDS 検索フォームへの読取専用検索を対象とした。コード、設定、業務データ、外部データの変更は実施していない。内蔵ブラウザは Windows ドメイン認証確認から進まず、認証済み画面の DOM と Console は確認できなかった。提示画像とデータベースの 500 件は一致した。
