# AI アシスタント専用画面の調査報告

## 1. 目的

第 1 階層の「タスクセンター」を「AI アシスタント」へ変更し、右下の浮動チャットと同じ Session、Task、SSE 状態を使用する専用画面を提供する。

## 2. 調査結果

### 2.1 既存構造

1. 第 1 階層の `tasks` は `/tasks` へ対応し、専用実装を持たない共通 Module 画面だった。
2. AI アシスタントは `AuthenticatedPortal` の末尾で 1 個だけ描画し、右下の浮動ウィンドウとして Session と SSE 状態を保持していた。
3. ロール権限マトリクスは `ai.assistant` の並び順を持っていたが、表示名辞書に AI アシスタントの項目がなかった。

### 2.2 採用構造

1. `AiAssistantChat` を Portal Content 内へ移し、同じ Component Instance を維持する。
2. 通常画面では `floating`、AI アシスタント画面では `page` を指定する。
3. `page` では右下入口を描画せず、会話履歴を左側へ常時表示する。
4. 浮動ウィンドウの最大化操作は `/ai-assistant` へ遷移する。
5. Session 選択、入力、Task、SSE 接続は表示方式の切替で再生成しない。

## 3. 権限

1. 第 1 階層メニュー、専用画面、浮動入口は `ai.assistant.use` で統一する。
2. ロール権限分配画面へ「AI アシスタント」行と「実行」列を表示する。
3. 権限を持たない利用者が AI アシスタント URL を指定した場合は、利用可能な第 1 階層画面へ正規化する。

## 4. URL

正式 URL は `/ai-assistant` とする。旧 `/tasks` は `tasks` ルートとして読み取り、Portal の状態確定時に `/ai-assistant` へ置換する。

## 5. 表示

1. デスクトップでは左側 292 ピクセルを会話履歴、右側を会話本文と入力欄に使用する。
2. 会話本文は最大 980 ピクセルで中央配置する。
3. 720 ピクセル以下では会話履歴を上、会話本文を下へ配置する。
4. AI アシスタント画面では組織コンテキストを表示しない。

## 6. 検証結果

1. 定向テスト 45 件が成功した。
2. 完全テストは Gateway 127 件、Worker 4 件、Portal 96 件が成功した。
3. Production build と運用スクリプトが成功した。
4. Portal 公開、nginx 設定検査、Gateway health、HTTPS 応答を確認した。
5. 認証後ブラウザーでメニュー、専用画面、浮動入口、最大化、旧 URL 移行、権限マトリクスを確認した。
6. ブラウザーコンソールの error、warning は 0 件だった。
7. CAG 8000 プロセスは公開前後で同一 PID と開始時刻を維持した。
