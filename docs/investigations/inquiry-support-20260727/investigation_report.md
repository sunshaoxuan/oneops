# 問合支援实现调查报告

## 调查范围

本次调查覆盖真实 UPDS 网站登录、产品入口、查询表单、结果表格、工单详情结构、OneOps 权限边界、AI 设置消费接口、前端导航和发布验证路径。

## 真实网站结论

1. 登录入口使用 CSRF 表单和 Cookie 会话。
2. UPDS 工单查询入口为 `/sssite/upds/helpdesk/`。
3. 查询支持状态、创建日期和负责人条件。状态值包含 OPEN、CLOSED 和细分状态。
4. 查询结果表为 `id_table_incident_list`，工单详情入口使用 `/sssite/upds/helpdesk/{ticketNo}/`。
5. 详情通过“サポートセンターへの追加質問”“サポートセンターからの回答”“ヘルプデスクコメント”等标题区分追加提问、公开回答和内部评论。
6. 真实网站可能显示总件数并限制当前页面结果数，因此接口同时保留总件数、显示件数和截断标记。

调查过程中仅记录结构、字段和路由。客户正文、联系方式、Cookie、CSRF Token 与登录秘密均未写入调查文档或测试夹具。

## OneOps 接入结论

1. 查询与详情 API 复用 OneOps 现有认证、CSRF 和网关边界。
2. `inquiries.use` 作为节点权限，授予系统管理员、运维人员和只读用户。
3. 真实网站设置复用系统管理权限。
4. Model 与 Agent Gateway 设置通过当前公共仓储接口读取，本任务不修改现有 AI 设置页面或 Gateway 设置实现。
5. 辅助任务保存 Provider、运行状态、分析结果和草案，不保存发送给 Provider 的原始工单上下文。

## 实现策略

真实网站适配器执行同源 HTTPS 校验、会话登录、响应大小限制、超时和 HTML 标准化。详情解析使用稳定内容哈希生成问题键和消息键。

AI 分析在用户点击入口后创建异步任务。模型输入执行联系方式与秘密信息脱敏，并将工单内容标为不可信证据。Provider 失败直接记录失败原因。

前端通过大型右侧抽屉展示固定标题区、可折叠问题块和左右聊天布局。草案只在浏览器会话内编辑和复制。
