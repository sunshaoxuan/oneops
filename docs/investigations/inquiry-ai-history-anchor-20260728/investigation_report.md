# 問合せ AI 補助履歴の表示位置調査

## 目的

保存済み AI 補助履歴が問合せ詳細ドロワーの上部へ集約され、補助を実行した質問または発言との関係を把握しにくい問題を調査した。

## 確認結果

従来の補助実行データには `question_key` と任意の `focus_message_key` が保存されていた。質問直後と次の返信位置を区別する項目が存在しないため、画面を再表示した時に実行位置を完全には復元できなかった。

現在の画面内セッションは `QUESTION`、`MESSAGE`、`NEXT_REPLY` を保持していたが、この位置種別は API とデータベースへ渡していなかった。保存済み履歴はドロワー上部の共通領域から遅延取得されていた。

## 対応

1. 補助実行へ `assist_anchor` を追加し、`QUESTION`、`MESSAGE`、`NEXT_REPLY` を保存する。
2. `MESSAGE` は `focus_message_key` を必須とし、その他の位置では `focus_message_key` を禁止する。
3. 既存データは `focus_message_key` がある場合に `MESSAGE`、ない場合に従来の実行位置である `NEXT_REPLY` へ移行する。
4. 詳細表示時に読み取り専用履歴を取得し、質問、発言、次の返信の各位置へ初期状態で閉じて表示する。
5. 過去の解析修正で質問キーが変化した履歴は、質問が 1 件だけの場合にその質問の次の返信位置へ復元する。
6. 複数質問のため位置を一意に解決できない履歴だけを、位置不明と明示してドロワー末尾へ表示する。

## 安全性

履歴取得は `GET` のみを使用する。詳細表示と履歴展開では AI 補助タスクを作成しない。AI 補助タスクは従来どおり利用者が電球または AI 補助操作を選択した時だけ作成する。

## 互換性

旧クライアントから `anchor` が送信されない場合は、`focusMessageKey` があれば `MESSAGE`、なければ `NEXT_REPLY` として受け付ける。
