# 問合せ全体分析の段階判定と添付解析調査

## 1. 目的

顧客公開回答がまだない新規問合せで、問合せ全体分析がサービス品質と顧客評価を固定的に表示する事象を修正する。あわせて、PPTX 内の画面画像を AI 分析の証拠として利用できるようにする。

## 2. 実運用事象の安全な構造確認

対象問合せは次の状態であった。問合せ本文、添付画像、顧客情報、モデル応答本文は証跡へ保存していない。

- ステータスは未回答の OPEN
- 顧客質問は 1 回
- 顧客公開回答は 0 件
- 内部記録は存在
- 顧客評価は存在しない
- PPTX 添付は 1 件
- PPTX のスライド文字列は 0 文字
- PPTX の内包画像は 1 件

## 3. 原因

### 3.1 対応段階

`FULL_TICKET` の出力契約は `overallAssessment.serviceQuality` を常に必須文字列としていた。Model API は未回答の問合せでもサービス品質を埋める必要があり、対応途中を完了後評価の形式へ当てはめていた。

### 3.2 顧客評価

Model API は顧客評価がない場合に空配列を返していた。Portal が空配列でも顧客評価領域を固定表示していたため、評価対象があるように見えていた。

### 3.3 添付

従来の Prompt は添付 ID、ファイル名、形式だけを含み、ファイル本文と画像を取得していなかった。PPTX に画面画像だけがある場合、モデルが確認できる証拠は存在しなかった。

## 4. 対応段階の契約

サーバーが問合せ状態と公開回答の有無から次を確定する。

| 段階 | 判定 | サービス品質 | 顧客評価 |
| --- | --- | --- | --- |
| `PRE_RESPONSE` | 全問題に公開回答なし | `null` | 存在しない場合は空配列 |
| `IN_PROGRESS` | 過去回答あり、最新問題は未回答 | `null` | 存在しない場合は空配列 |
| `RESPONSE_REVIEW` | 最新問題まで公開回答あり、OPEN | 評価する | 存在時だけ評価 |
| `CLOSED_REVIEW` | 最新問題まで公開回答あり、CLOSED | 評価する | 存在時だけ評価 |

`PRE_RESPONSE` と `IN_PROGRESS` の画面はサービス品質と是正対応の語を使用せず、現在の対応段階、調査進捗、未確認事項、現在のリスク、次の対応を表示する。

## 5. 添付解析

OneOps は実サイトの認証済みセッションを使って添付を取得し、次を解析する。

- PPTX、DOCX、XLSX の Open XML 文字列
- PPTX、DOCX、XLSX に内包された PNG、JPEG、WebP、GIF
- 直接添付された PNG、JPEG、WebP、GIF

抽出文字列は既存の連絡先と秘密情報マスクを通す。画像は AI 補助を手動実行した場合だけ、選択中の Model API へ高精度画像入力として渡す。ファイル内容と画像内の指示は信頼しない。

## 6. Provider 境界

現行 `gpt-5.6-terra` の OpenAI 互換 Chat Completions 端点へ、業務情報を含まない 1 ピクセル PNG を送信した。HTTP 200、回答文字列、Token 使用量を確認し、画像入力が利用可能であることを確認した。

CAG の現行 Task API は `project_id`、`prompt`、`conversation_id`、実行プロファイルなどを受けるが、構造化添付リソースを受けない。Model API で現行要件を実現し、Agent Gateway で視覚添付を使用するための追加契約を別紙へ記録する。

## 7. 実問合せによるモデル契約検証

本文を出力しない構造検証で、次を確認した。

- `reviewStage=PRE_RESPONSE`
- 質問 1 件、`NO_PUBLIC_REPLY`
- 顧客評価との関係は 0 件
- `serviceQuality=null`
- 最終結論なし
- PPTX は解析成功 1 件
- 視覚証拠 1 件
- 添付の未対応、失敗、画像省略は 0 件

## 8. 結論

事象の原因はモデル能力ではなく、段階を持たない固定出力契約と添付本文を取得しない入力経路であった。対応段階をサーバーで確定し、Model API の視覚入力へ解析済み添付を渡すことで、未回答案件を完了後評価として扱う問題と画面画像を参照できない問題を同時に解消できる。
