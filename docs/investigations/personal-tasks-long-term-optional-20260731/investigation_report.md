# 個人タスク長期確認項目任意化 調査・実装記録

更新日: 2026-07-31
対象バージョン: OneOps 0.7.1

## 1. 要求

長期タスクを定期確認型ではなく条件発動型として扱います。発動条件は未設定、日付条件、意味条件のいずれか一つで、意味条件は AI Prompt に記述します。

## 2. 影響範囲

| 層 | 変更内容 |
| --- | --- |
| API 正規化 | 長期タスクの発動日時と AI Prompt を任意にし、両方の同時指定を拒否する |
| データベース | `personal_tasks_schedule_check` を更新し、日付条件と意味条件の同時保持を拒否する |
| 画面 | 長期タスク編集から確認周期を除去し、日付条件と意味条件の選択を表示する |
| 文書 | 長期タスクの保存条件と定期確認対象を明記する |

発動条件が NULL の長期タスクは「長期」ビューに残ります。日付条件を設定した場合はその日時を表示し、意味条件を設定した場合は AI Prompt を判定条件として扱います。長期タスクには日次の定期 Prompt 実行を行いません。

## 3. 実装結果

`0.7.0` の既存スキーマ定義を更新し、稼働中データベースには `023_allow_optional_long_term_review.sql` と `024_long_term_trigger_condition.sql` を適用しました。既存の周期項目は NULL へ整理し、期限タスクの期限必須を保持します。移行ファイルは同一データベースへ連続適用しても制約を重複作成しません。

## 4. 検証

- Gateway 個人タスクテスト: 10 件成功
- Portal Shell テスト: 120 件成功
- Portal Shell 本番ビルド: 成功
- PostgreSQL 移行再実行: 成功
- 日付条件と意味条件を NULL にした長期タスクのトランザクション挿入: 成功、ロールバック済み
- 日付条件と意味条件の同時指定: API とデータベースで拒否
- 画面表示、コンソール、正式サイト公開の証跡: `evidence_index.md` に記録

## 5. ロールバック

アプリケーションは `v0.7.0` へ戻せます。データベース制約だけを戻す場合は、`024_long_term_trigger_condition.sql` 適用前の制約定義を新しい番号の移行として追加します。周期項目を旧画面へ戻す場合は、整理済みの周期値を復元できるバックアップが必要です。
