# ロール・権限データ可視性監査記録

更新日: 2026-08-03
対象バージョン: OneOps 0.8.0

## 調査対象

ロール・権限画面で「データがありません」と表示された事象を対象に、正式データベース、Spring Boot サービス、JSON 応答、Portal の表示処理を順に確認した。

## 結論

ロール、権限、ロール権限関連のデータは削除されていなかった。正式データベースには `roles=3`、`permissions=20`、`role_permissions=39`、`users=12`、`user_role_assignments=12` が存在し、12 利用者すべてにロール割当が残っていた。

画面が空に見えた原因は、Spring のロール取得処理が PostgreSQL の `java.sql.Array` をそのまま応答 Map に格納していたことだった。JdbcTemplate の接続終了後に Jackson が `PgArray` をシリアライズしようとしたため、`roles` API の JSON 化が失敗していた。Portal の `RoleManagement` はクエリエラーを空配列として描画していたため、利用者には API 障害がデータ消失として見えていた。

## 修正

`IdentityService.rolesAndPermissions()` で PostgreSQL 配列、Java 配列、Collection を接続に依存しない `List<String>` へ変換してから応答するようにした。空配列は空のリストとして返し、JSON シリアライズ時に閉じた JDBC 接続へ戻らないようにした。

## 現場反映

修正後に Spring Boot JAR を再作成し、`OneHR Operations Compat Gateway` を再起動した。ヘルスチェックは `status=UP`、Spring サービスのバージョンは `0.8.0` を返した。稼働中データベースに対して同じロール取得処理を実行し、3 ロールと 20 権限を取得した後、Jackson で 4668 バイトの JSON へシリアライズできることを確認した。

## 再発防止

1. JDBC の `Array`、`ResultSet`、接続依存オブジェクトを Web 応答へ直接渡さない。
2. Repository と Service の境界で JSON 用のプリミティブ値へ変換する。
3. Portal の一覧画面はクエリエラーを空データとして扱わず、エラー表示を優先する。
4. ロール、権限、組織、環境、製品、個人タスクの件数監査をリリース後の確認項目に追加する。
