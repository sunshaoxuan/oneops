# 問合支援カテゴリー階層選択の調査報告

## 調査対象

問合支援のカテゴリーと分類・調査結果の選択操作を対象とした。

## 確認結果

実サイトの検索画面は、最上位項目から子項目を順に展開する階層メニューを使用する。OneOps 0.6.0 は実サイトから取得した 500 件のカテゴリーを完全パス付きの単一選択一覧へ展開していた。値の検索は可能であったが、通常の閲覧では全階層が同じ列に並び、対象へ到達するための走査量が大きかった。

## 原因

API が返す `value` と完全パスの `label` を、そのまま平坦な Select の options として渡していた。取得データには階層の完全パスが含まれており、画面側で親子構造を復元できる。

## 対応

完全パスを ` > ` で分解し、元の `value` を保持した階層木と、選択値から祖先値列へ戻す索引を構築する。カテゴリーと分類・調査結果は同じ階層選択を使用する。

通常操作は最上位項目だけを最初に表示し、対象項目に応じて子項目を隣の列へ展開する。中間階層の選択、キーワード検索、選択後の完全パス表示を維持する。検索 API へ送信する値は従来と同じ実サイトの末端または中間階層 ID とする。

## 影響範囲

画面の選択操作と表示だけを変更する。Gateway、実サイトへの検索パラメーター、認証情報、CAG には変更を加えない。
