# 問合システム顧客 Code 台帳移管 調査及び実装記録

更新日: 2026-08-05

## 当初目的

外部システムの接続及び業務主キー対応を一般業務画面から変更できないようにし、問合システム顧客 Code を組織機関台帳で管理する。

## 変更前の状態

問合システム顧客 Code は `customer_information_settings` に保存されていた。編集欄は顧客情報の基本情報に配置され、`environments.write` を持つ利用者が変更できた。

この配置では、組織機関台帳の基本項目と外部システム対応の管理境界が画面上で分離されず、一般業務画面から台帳級設定を変更できた。

## 設計判断

1. 問合システム顧客 Code は組織機関台帳の外部システム対応項目とする。
2. 編集入口は基本台帳の組織機関追加及び編集 Modal に限定する。
3. 保存権限は `organizations.write` とする。
4. 顧客情報の基本情報は参照専用とし、外部 Code の入力欄と保存操作を削除する。
5. 対応値は既存の `customer_information_settings` に保存し、組織機関物理 ID で強参照する。
6. 対応レコード自身に UUID 物理 ID を追加する。
7. 未照合の対応値が空欄の場合は問合検索時に機関 Code を使用する。外部サイトで照合済みの場合は、機関 Code と同じ値も対応レコードとして保存する。
8. 旧顧客設定更新 API は削除し、組織機関追加及び更新 API に統一する。

## 実装経路

`OrganizationPage` の Form から `OrganizationInput.inquiryCustomerCode` を送信し、Gateway の組織機関検証を経て、組織機関保存 SQL と外部 Code 対応 SQL を一つのデータ変更文で実行する。

組織機関一覧は `customer_information_settings` を物理 ID で結合し、対応値が空の場合は機関 Code を有効値として返す。顧客問合一覧は同じ有効値を外部問合ソースへ送信する。

2. API Client の組織機関契約
3. Gateway の組織機関検証、保存及び顧客設定更新経路
4. Migration 030、031
