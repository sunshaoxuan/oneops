# 問合支援 検索結果並べ替え調査

調査日: 2026-07-30

## 1. 要求

問合支援の検索結果を利用者が必要に応じて並べ替えられるようにし、初期表示を更新日時順とする。

## 2. 変更前の経路

検索画面は `InquirySupportPage.tsx` から `searchInquiryTickets` を呼び出す。Gateway は UPDS の検索 HTML を取得し、`parseInquirySearchHtml` が次の表示項目へ変換する。

* 問合せ No.
* 件名
* 担当者
* ステータス
* 更新日時
* 回答希望日
* 顧客

変更前の Ant Design Table 列には `sorter` と初期並べ替え指定が存在せず、UPDS から返された順序をそのまま表示していた。

## 3. 実装

全 7 列へ昇順と降順の並べ替えを追加した。問合せ No. と文字列列には数字を考慮する文字列比較、日付列には日時比較を使用する。

更新日時列へ `defaultSortOrder: "descend"` を設定し、初期表示で新しい更新日時を先頭へ配置する。並べ替え対象は UPDS から今回返された全件である。UPDS の表示上限を超えた未取得レコードは対象外とし、既存の省略警告を継続表示する。

## 4. 継続的デリバリー競合

実装後の自動公開で、常時稼働監視が公開器による Gateway 計画停止を障害と判断し、Gateway を再起動した。公開器は 8092 番ポートの安定解放を確認できず、公開済み index をロールバックした。

公開器と常時稼働監視が共通 Mutex `Global\OneOpsContinuousDelivery` を使用するように修正した。公開中は常時稼働監視が復旧を見送り、常時稼働確認中に開始した公開は最大 5 分間待機する。

修正後、スクリプト変更を検出した自動公開が 2 回連続で成功した。手工公開も成功した。

## 5. 結論

検索結果の全表示列は利用者操作で昇順と降順を切り替えられる。初期状態は更新日時の降順である。常時稼働監視と継続的デリバリーの Gateway 再起動も競合しない。
