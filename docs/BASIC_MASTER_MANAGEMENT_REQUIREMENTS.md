# 基本档案管理需求

更新时间：2026-07-25

## 管理入口

“管理”模块使用“系统管理”作为页面级入口，并在页面内容上方提供横向分组二级菜单。基本档案目录与具体档案维护区域分开，后续新增基本档案时，应在“基本档案管理”下拉菜单登记并复用统一的查询、新增、编辑和校验模式。

“管理”属于系统级功能，不显示组织机关的“共通上下文”选择器，也不按当前组织机关过滤任何系统档案。

系统管理的二级菜单分组固定为：

1. `基本档案管理`：组织区分、产品与版本。
2. `用户管理`：用户管理、角色与权限、认证审计。

用户、角色、权限和认证审计属于独立的身份与访问管理功能，不归入基本档案管理。系统管理不保留固定左侧二级导航。页面顶部显示完整分组名称，具体功能项放在对应分组的下拉菜单中，并通过独立入口直接进入功能页面。

当前纳入管理的基本档案：

1. 组织区分档案。
2. 产品、版本和版本功能模块档案。

## 强制数据规则

1. 每一种基本档案及其每一条记录都必须具有独立、稳定的物理 ID。
2. 普通画面隐藏物理 ID。
3. Code 是面向业务的唯一标识，名称是业务信息。
4. 其他档案或业务记录引用基本档案时，必须保存基本档案的物理 ID。
5. 数据库必须使用外键约束保证引用完整性。
6. Code 和名称不得承担强关联外键。

## 组织区分档案

组织区分档案维护物理 ID、区分 Code 和区分名称。管理画面提供查询、新增和编辑，列表只展示 Code、名称和操作图标。

基本档案表格使用易读的大字号。业务 Code 使用无边框、无底色的纯文本样式，并保持清晰的字符间距。

组织机构通过 `organizations.classification_id` 引用组织区分档案。修改区分 Code 或名称时，组织机构引用关系保持不变。

删除功能暂不开放，避免删除已被组织机构引用的区分档案。后续增加作废机制时，应保留物理 ID 和历史引用。

## 产品、版本和功能模块档案

产品与版本画面的说明文案直接表述“管理产品、版本和功能模块”，不在业务画面使用主子孙等数据结构术语。

产品、版本和功能模块均提供新增和编辑入口：

1. 选择产品后，可以编辑所选产品的 Code、名称和简称。
2. 选择版本后，可以编辑所选版本的标准版本和显示版本。
3. 每条功能模块记录提供编辑图标，可以编辑模块 Code、名称和简称。
4. 所有更新根据稳定物理 ID 定位记录。修改 Code、名称或版本文字时，环境对产品版本及模块的既有引用保持不变。
5. 功能模块是产品范围内的稳定档案。同一稳定模块出现在多个版本时，Code、名称和简称的修改同步应用到这些版本。
6. 产品档案写操作统一要求 `catalog.write` 权限，服务端继续执行输入校验、唯一性约束和引用完整性约束。
7. 版本列表按照版本号的数字分段自然升序排列。例如 `2.9.2` 位于 `2.11.1` 之前，`V7` 位于 `V10` 之前。
