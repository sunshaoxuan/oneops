# 基本台账需求

更新日：2026-08-03

## 管理入口

“基本台账”作为左侧一级入口，紧邻并位于“系统管理”上方。基本台账页面在内容上方提供横向功能菜单，台账目录与具体维护区域分开。后续新增基本台账时，应在该入口登记，并复用统一的查询、新增、编辑和校验模式。

“基本台账”属于系统共通功能，不显示组织机关的“共通上下文”选择器，也不按当前组织机关过滤台账数据。

基本台账当前包含：

1. `组织区分`：组织机关引用的区分台账。
2. `组织机关`：组织机关台账的查询、新增和编辑。
3. `产品与版本`：产品、版本和版本功能模块台账。

基本台帳の横型メニューは「組織区分」、「組織機関」、「製品・版数」の順で表示し、基本台帳への初回遷移時は「組織区分」を表示する。権限によって参照できない台帳がある場合は、この表示順で最初に参照できる台帳を表示する。

左側第1階層の「組織機関」入口は基本台帳へ移動する。基本台帳の入口と参照には `catalog.read` を必須とし、権限変更後の代理ログインでも対象利用者の最新権限を適用する。基本台帳内では、`organizations.read` がある場合に組織機関台帳を表示する。組織区分及び製品・版数台帳は `catalog.read` で参照でき、追加・編集操作は `catalog.write` がある場合だけ表示する。組織機関の追加・編集操作には `organizations.write` を必須とする。

系统管理保留 AI 设置、问询设置、用户管理、角色与权限及系统操作审计。用户、角色、权限和认证审计属于独立的身份与访问管理功能。系统管理不再承载基本台账。

AI 设置属于独立的系统设置功能，详细需求参见
`D:\nginx\docs\AI_SETTINGS_REQUIREMENTS.md`。

当前纳入管理的基本台账：

1. 组织区分台账。
2. 组织机关台账。
3. 产品、版本和版本功能模块台账。

## 强制数据规则

1. 每一种基本台账及其每一条记录都必须具有独立、稳定的物理 ID。
2. 普通画面隐藏物理 ID。
3. Code 是面向业务的唯一标识，名称是业务信息。
4. 其他台账或业务记录引用基本台账时，必须保存基本台账的物理 ID。
5. 数据库必须使用外键约束保证引用完整性。
6. Code 和名称不得承担强关联外键。

## 组织区分档案

组织区分档案维护物理 ID、区分 Code 和区分名称。管理画面提供查询、新增和编辑，列表只展示 Code、名称和操作图标。

基本档案表格使用易读的大字号。业务 Code 使用无边框、无底色的纯文本样式，并保持清晰的字符间距。

組織機関台帳は問合システム顧客 Code を外部システム対応項目として表示及び編集する。未設定時は機関 Code を使用し、一般業務画面からは変更できない。変更には `organizations.write` を必須とする。システムは登録済みの問合サイトデータソースを 1 日単位で読み取り、Code と名称又は略称が一意に一致する対応を物理 ID 参照で自動補足する。競合及び未一致は既存値を変更しない。

组织机构通过 `organizations.classification_id` 引用组织区分档案。修改区分 Code 或名称时，组织机构引用关系保持不变。

删除功能暂不开放，避免删除已被组织机构引用的区分档案。后续增加作废机制时，应保留物理 ID 和历史引用。

## 产品、版本和功能模块档案

产品与版本画面的说明文案直接表述“管理产品、版本和功能模块”，不在业务画面使用主子孙等数据结构术语。

产品、版本和功能模块均提供新增和编辑入口：

1. 选择产品后，可以编辑所选产品的 Code、名称和简称。
2. 选择版本后，可以编辑所选版本的标准版本和显示版本。
3. 每条功能模块记录提供编辑图标，可以编辑模块 Code、名称和简称。
4. 所有更新根据稳定物理 ID 定位记录。修改 Code、名称或版本文字时，环境对产品版本及模块的既有引用保持不变。
5. 功能模块是产品范围内的稳定档案。同一稳定模块出现在多个版本时，Code、名称和简称的修改同步应用到这些版本。
6. 产品档案写操作统一要求 `catalog.write` 权限，服务端继续执行输入校验、唯一性约束和引用完整性约束。
7. 版本列表按照版本号的数字分段自然升序排列。例如 `2.9.2` 位于 `2.11.1` 之前，`V7` 位于 `V10` 之前。
