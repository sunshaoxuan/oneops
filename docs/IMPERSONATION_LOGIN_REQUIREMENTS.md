# 代理ログイン要件

対象バージョン: OneOps 0.7.2

## 目的

システム管理者が指定した利用者の権限、画面表示、業務機能を確認できるように、対象利用者のセッションを代理で開始します。代理中の操作は対象利用者の権限とデータ境界で実行します。

## 画面

1. ヘッダーの利用者表示をクリックするとドロップダウンを表示します。
2. プロフィール操作を表示します。
3. 代理ログイン中は「代理ログインを終了」を表示します。
4. 「ログアウト」はドロップダウンの最後の項目に固定します。
5. システム管理のユーザー管理では、権限を持つ管理者だけが有効な別利用者の代理ログイン操作を実行できます。
6. 代理ログイン中は対象利用者の画面に実行者を示す警告帯を表示します。

## 権限とセッション

1. 新しいシステム権限は `identity.users.impersonate` です。標準の `SYSTEM_ADMIN` ロールだけへ初期付与します。
2. 代理開始時は `auth_sessions.user_id` を対象利用者、`auth_sessions.impersonator_user_id` を管理者として保存します。
3. セッション解決、個人タスク、環境情報、問い合わせ、AI助手の認可は対象利用者の権限を使用します。
4. 自分自身への代理ログイン、代理中の多重代理ログイン、PENDING または SUSPENDED 利用者への代理ログインは拒否します。
5. 代理終了時は現在の代理セッションを失効させ、実行者の新しい通常セッションを発行します。
6. 実行者が有効でない場合は代理セッションを失効させ、通常ログインを要求します。

## 操作監査

次のイベントを `auth_audit_events` に保存します。

- `IMPERSONATION_STARTED`
- `IMPERSONATION_START_FAILED`
- `IMPERSONATION_STOPPED`
- `IMPERSONATION_STOP_FAILED`

監査イベントには実行者、対象利用者、接続元、ユーザーエージェント、結果を保存します。パスワード、セッション値、CSRF 値は保存しません。

## API

- `POST /api/work-center/v1/auth/impersonation/{userId}`
- `POST /api/work-center/v1/auth/impersonation/stop`
- `GET /api/work-center/v1/auth/session`

すべての変更要求は現在セッションの CSRF 値を要求します。認証情報とセッション応答はキャッシュしません。

## 受入条件

1. ログアウトが利用者ドロップダウンの最後に表示される。
2. 管理者が有効な別利用者へ代理ログインできる。
3. 代理中に対象利用者の権限だけが適用される。
4. 代理終了で管理者へ戻り、対象利用者の画面データがブラウザーキャッシュへ残らない。
5. 権限不足、自己指定、多重代理、無効利用者が拒否される。
6. 開始、終了、失敗が監査画面から確認できる。
