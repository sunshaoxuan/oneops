# 個人タスク要件

更新日: 2026-08-12
対象バージョン: OneOps 0.18.21

## 1. 目的

個人タスクは、OneOps の各利用者が期限のある作業、継続的な取り組み、外部サービスで自分に割り当てられた案件を一つの場所で確認し、実際の次の行動へ結び付ける機能です。

個人タスクは組織機関コンテキストに属しません。タスク、候補、外部接続、同期履歴、Prompt 実行履歴は、ログイン中の OneOps ユーザー物理 ID に所属します。

## 2. ナビゲーション

第 1 階層の表示順序は次のとおりです。

1. ワークベンチ
2. タスク
3. 環境情報
4. 問合支援
5. 製品構築
6. AIアシスタント
7. ナレッジ
8. コードインサイト
9. レポート
10. 基本台帳
11. システム管理

個人タスクは `/tasks`、AIアシスタントは `/ai-assistant` を使用します。個人タスクには `personal.tasks.use`、AIアシスタントには `ai.assistant.use` の権限が必要です。

製品構築、ナレッジ、コードインサイト及びレポートの第1階層入口も独立した権限で制御します。製品構築は `builder.use`、ナレッジは `knowledge.use`、コードインサイトは `code.insight.use`、レポートは `reports.read` を使用します。前三者は業務機能を実行する権限、レポートは情報を閲覧する権限としてロール・権限マトリクスへ表示します。

## 3. タスク

### 3.0 タブの未完了件数表示

タスク画面の「今日・期限超過」「予定」「長期」「候補」タブは、解決が必要な件数をタブ名の後ろに表示します。件数が 0 の場合は表示しません。「完了」タブには件数を表示しません。期限タスクは当日終了時刻以前を「今日・期限超過」、それより後を「予定」とし、完了状態のタスクは各件数から除外します。

### 3.1 種別

- 期限タスクは期限日時を必須とします。
- 長期タスクは定期タスクに限定せず、発動条件を持つ継続作業として管理します。発動条件は未設定、日付条件、意味条件のいずれか一つです。
- 日付条件は任意の発動日時です。意味条件は AI Prompt で記述し、日付条件とは同時に設定できません。
- 発動条件を設定しない長期タスクも保存できます。確認周期と確認間隔は使用せず、既存データの周期項目は NULL へ整理します。

### 3.2 状態と優先度

状態は未着手、対応中、確認待ち、完了を使用します。優先度は低、通常、高、至急を使用します。

画面は今日・期限超過、予定、長期、候補、完了へ分けます。タイトル、説明、外部キー、外部状態を検索対象とします。

### 3.3 説明と Prompt

通常の説明と AI Prompt は別項目として保存します。Prompt には、AI に依頼する調査、整理、判断基準を記述します。

手動実行と定期実行は、システムの AI 設定にある有効な既定 `GENERAL` OpenAI Model を使用します。各 Prompt 実行は現在ユーザーが所有する新しい AIアシスタント Session を作成し、Model 設定物理 ID、Model ID、推理レベル及び速度表示を Session へ保存します。

タスクの名称、種別、状態、説明、Prompt 及び外部参照を利用者入力として OneOps Local Task へ保存します。OneOps GPT Runner は Session の Model と推理レベルを使用し、OpenAI Responses API を `store: false` かつ `stream: true` で直接呼び出します。会話履歴、Streaming 及び終端は AIアシスタントと同じ OneOps Local Task/Event Ledger へ保存し、結果は作成済みの Session で確認します。AI の提案はタスクを自動更新しません。

個人タスクの AI 実行に Agent Gateway、CAG Project、Runtime Profile 及び CAG Task API を使用しません。Provider Error 時は CAG、別 Model 及び別 Endpoint へ迂回せず、対象 Local Task と Prompt 実行履歴を失敗へ確定します。

期限タスクで定期実行を明示的に有効にした AI Prompt は、次の条件をすべて満たす場合に 24 時間に 1 回まで実行します。

- Prompt が空でない。
- タスクが完了またはアーカイブされていない。
- 所有者が `ai.assistant.use` 権限を持つ。
- 過去 24 時間に Prompt 実行履歴がない。

長期タスクの AI Prompt は意味条件として保存します。長期タスクは日次の定期実行対象にせず、日付条件または将来のイベント条件に応じて判定するための情報として扱います。

## 4. 外部接続

### 4.1 所有権

外部サイトの接続先、認証情報、検索条件及び同期間隔はシステム管理の「外部タスク」で集中管理します。個人タスク画面には接続、認証情報表示、コピー又は同期設定を配置しません。

各 OneOps 利用者は `user_external_profiles` により外部システム物理 ID と関連付けます。域、Backlog、問合せサイト及び将来追加する外部システムのユーザー ID 又は Code は同じ表で管理します。強参照は OneOps ユーザー物理 ID、外部システム物理 ID及びユーザー外部档案物理 ID を使用します。

### 4.2 問合せサイト

問合せサイト接続は `https://ss.onehr.jp/`、ログインユーザー、パスワード及び候補検索条件を保存します。担当者は本人、外部 Options から選択した特定担当者又は担当者未設定のいずれかを必須とし、ログイン ID と表示名を外部担当者 ID の代用にしません。状態は OPEN、CLOSED 及び実サイトの詳細状態を使用します。顧客、サブステータス、カテゴリー、分類・調査結果、キーワード、作成期間、回答希望期間及び更新期間を任意条件として使用できます。検索と解析は既存の問合支援ソースクライアントを再利用します。

問合支援のシステム共通接続は従来どおり維持します。個人タスクの接続とは別レコード、別権限、別利用目的で管理します。

### 4.3 Backlog

Backlog 接続は HTTPS の Backlog Space URL とシステム共通 API Key を使用します。ユーザー外部档案に保存した Backlog ユーザー物理 ID を `assigneeId[]` に指定し、本人が担当する課題をプロジェクト ID、状態 ID、更新日で絞り込みます。

取得は 100 件単位でページングし、同一利用者の要求を直列に実行します。429 応答は `X-RateLimit-Reset` を上限 60 秒として 1 回再試行します。API Key をログ、監査詳細、エラー本文へ記録しません。

## 5. 候補と外部状態

外部案件は最初に候補として保存します。候補の採用時に新しい個人タスクと外部参照を作成します。

候補を除外した場合は、外部更新日時が変化するまで候補へ再表示しません。外部更新が確認された場合は、再確認できるよう候補へ戻します。

検索条件は正の Revision を持ちます。条件変更後又は利用者の明示操作で候補を再生成し、今回の検索結果に含まれなかった `PENDING` 候補を `STALE` へ移します。`ADOPTED` と `DISMISSED` は再生成で変更しません。同じ外部案件が条件へ再一致した場合は `STALE` から `PENDING` へ戻します。

外部検索が表示上限で切り捨てられた場合、要求状態と返却状態が一致しない場合又は要求担当者と返却担当者が一致しない場合は同期全体を失敗とし、候補を更新しません。

同期は外部キー、URL、状態、担当者、作成日時、更新日時を保存します。外部状態は OneOps のタスク状態を自動上書きしません。

## 6. 同期

Gateway は 1 分ごとに同期対象を走査し、システム共通設定の既定 10 分間隔に達したユーザー外部档案を処理します。候補一覧と候補要約は 60 秒ごとに再取得します。

新しい `PENDING` 候補を作成したトランザクションは、同じユーザー物理 ID 宛てのシステム通知も一意に作成します。通知ベルは未読件数と通知一覧を表示し、通知選択時に候補タブへ移動して既読化します。

接続物理 ID 単位の PostgreSQL Advisory Lock を使用し、同じ接続の重複実行を防止します。外部接続 ID と外部オブジェクト ID の一意制約によって候補の重複登録を防止します。

同期履歴には起動種別、状態、取得件数、追加件数、更新件数、開始日時、完了日時、秘匿情報を除いたエラーを記録します。

## 7. データと API

すべての業務レコードは独立した UUID 物理 ID を持ちます。API と Repository は物理 ID を保持し、一般画面には内部 ID を表示しません。

主要 API は次のとおりです。

- `/api/work-center/v1/personal-tasks`
- `/api/work-center/v1/personal-task-summary`
- `/api/work-center/v1/personal-task-candidates`
- `/api/work-center/v1/personal-task-notifications`
- `/api/work-center/v1/personal-tasks/:id/prompt-runs`

更新には正の revision を必須とし、競合時は `409` を返します。Repository はすべての読み書きで `owner_user_id` と対象物理 ID を同時に使用します。

## 8. セキュリティと監査

認証情報は AES-256-GCM で暗号化します。暗号化 AAD には所有者ユーザー物理 ID と外部接続物理 ID を含めます。

認証情報を返す API は `Cache-Control: no-store` を使用します。表示、コピー、接続確認、同期、タスク変更、候補採用、Prompt 実行を操作監査へ記録します。

外部 URL は HTTPS に限定します。問合せサイトは `ss.onehr.jp`、Backlog は許可済み Backlog ドメインだけを受け付け、内部 IP や任意ホストへの接続を禁止します。

## 9. 将来拡張

接続器は接続確認、選択肢取得、増分取得、状態取得、標準形式への変換、外部 URL 生成の責務を持ちます。行事暦、チャット、その他の業務サイトは、この接続器境界へ追加します。

行事暦とチャットの実接続、会話からの自動タスク生成は 0.7.1 の対象外です。

## 10. 受入条件

1. 個人タスクがワークベンチ直後に表示され、AIアシスタントと異なる URL を使用する。
2. 期限タスクと長期タスクを作成、編集、完了、アーカイブできる。
3. 二人の利用者間でタスク、候補、接続、認証情報を相互参照できない。
4. 問合せサイトと Backlog の接続を保存、確認、同期できる。
5. 同じ外部案件を繰り返し同期しても候補が重複しない。
6. 外部案件を候補からタスクへ変換し、外部状態を確認できる。
7. 認証情報を星印表示、原文表示、コピーでき、操作監査へ記録される。
8. Prompt を実行すると既定 `GENERAL` OpenAI Model の新しい AIアシスタント Session と Local Task が作成され、同じ Session で Streaming と結果を確認できる。
9. 全テスト、本番ビルド、公開、ブラウザー、コンソール、画面証跡の検証に成功する。
10. 無効な担当者値、全件一覧への退行及び外部表示上限の切捨てが候補へ保存されない。
11. 検索条件の変更後に再生成すると、条件外の未採用候補が一覧から除かれ、採用済み候補と外部 Link が保持される。
12. 個人タスクから作成した Session の全 Task が作成時の Model と推理レベルを固定使用し、Provider Output、Token 使用量及び単一終端が OneOps Local Task/Event Ledger に保存される。
13. 個人タスクの AI 実行で Responses API だけが呼び出され、Agent Gateway 及び CAG Task の新規要求が 0 件である。
14. Provider Error 時に別の実行経路へ自動迂回せず、対象 Local Task と Prompt 実行履歴が対応する失敗状態へ確定される。
