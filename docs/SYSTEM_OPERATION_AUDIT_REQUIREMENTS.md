# 系统操作审计需求

## 1. 目标

系统需要记录用户从登录到业务能力调用的可审计过程。系统管理员通过系统管理中的“系统操作审计”节点查询记录。该节点是与“用户管理”平级的独立子功能，不归属于用户管理。

## 2. 权限

1. 审计查询继续使用 `audit.read`。
2. `SYSTEM_ADMIN` 默认拥有该权限。
3. 审计记录由服务端生成，前端不能提交或覆盖执行者、结果和耗时。

## 3. 记录范围

1. 本地登录、SSO、退出、注册和会话相关事件。
2. 用户与角色权限维护。
3. 工作台、组织机构、环境、基础档案、构建功能和系统设置 API 的使用。
4. 问询查询、工单详情、附件读取和问询源设置。
5. AI Model、Agent Gateway 和问询 AI 辅助能力调用。
6. 权限拒绝和业务失败。
7. 审计日志查询本身。

健康检查、会话状态轮询和实时事件长连接不生成高频业务审计记录。工作台后台刷新在一分钟内对同一用户和路径去重。

## 4. 审计字段

每条记录包含：

1. 独立物理 ID、时间、登录用户物理 ID和会话物理 ID。
2. 请求编号、来源地址和 User Agent。
3. 事件类型、使用能力、操作、对象类型和业务对象引用。
4. 结果、HTTP 状态和耗时。
5. 经筛选的业务上下文。
6. AI Provider、实际 Model 或 Gateway、AI 任务物理 ID和执行阶段。
7. Provider 返回的输入 Token、输出 Token和总 Token。

密码、Cookie、CSRF Token、API Key和完整密钥不得进入审计详情。

## 5. AI 过程

问询 AI 辅助至少记录任务创建、开始、完成和失败。完成记录保存 Provider 返回的 Token 用量。Provider 未返回 Token 字段时显示“未提供”，系统不进行估算。

## 6. 查询节点

系统操作审计支持按操作人、能力、结果和时间范围查询，默认返回最近 200 条，单次最多 500 条。页面使用摘要区、筛选区和结果区分层布局。列表显示事件、操作人、能力、动作、结果、对象、Token、耗时和时间。来源地址、请求编号、会话及已脱敏详情放入展开区域，避免主表拥挤。

## 7. 验收

1. 登录成功和失败均有记录。
2. 已登录用户调用业务 API 后生成含用户、能力、操作、结果和耗时的记录。
3. 问询 AI 任务具有创建、开始及完成或失败的过程记录。
4. Provider 返回 Token 用量时，任务和审计页面均可看到总量。
5. 审计页面可筛选并展开详情。
6. 普通用户无法读取审计 API。
7. 审计详情不包含密码、Cookie、CSRF Token或 API Key。
