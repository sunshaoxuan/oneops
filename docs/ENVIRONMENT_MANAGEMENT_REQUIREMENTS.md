# OneOps 环境信息管理总体规划

更新时间：2026年7月24日

状态：环境台账、产品三级档案、连接端点、凭据加密存储、权限和查看审计已实现。VPN 资料分析与候选审核继续按后续阶段实施

## 1. 功能目标

“环境信息”是以组织机构为边界管理客户运行环境、社内环境、产品版本、服务器、数据库、VPN、来源资料和确认历史的核心台账。界面功能名称统一为日文“環境情報”、中文“环境信息”、英文“Environment information”。

本功能必须解决以下问题。

1. 用户进入环境画面后，默认只看到当前选择客户的数据。
2. 每个客户可以建立环境组，并在组内新增、编辑、复制、归档和排序环境。
3. 每个环境可以关联一个或多个产品及其准确版本。
4. 客户环境和社内环境使用统一结构管理，同时保留清晰的范围与用途区分。
5. VPN 和其他连接信息可以从大量资料中形成待确认候选，经过人工审核后进入正式台账。
6. 每项重要信息都能追溯到来源文件、位置、确认人和确认时间。
7. 错误、过时、互相冲突和缺少依据的信息不能静默覆盖正式数据。
8. 密码、私钥和其他秘密信息与普通环境信息分开保存、授权和审计。

## 2. 统一业务定义

环境范围与环境用途使用两个独立维度。

1. 环境范围 `scope`

   1. `CUSTOMER`：位于客户侧或为客户服务的环境。
   2. `INTERNAL`：OneHR 社内使用的环境。

2. 环境用途 `purpose`

   1. `PRODUCTION`：生产环境。
   2. `VERIFICATION`：检证或受入环境。
   3. `DEVELOPMENT`：开发或维护环境。
   4. `TRAINING`：培训、演示或学习环境。
   5. `OTHER`：无法归入上述用途的环境。

3. 环境状态 `status`

   1. `ACTIVE`：当前有效。
   2. `PREPARING`：构筑中或切换准备中。
   3. `SUSPENDED`：暂时停止。
   4. `RETIRED`：已经退役并保留历史。

固定维度不得使用普通标签代替。普通标签只用于补充业务分类。

## 3. 现状调研结论

### 3.1 OneOps 当前状态

1. OneOps 的“环境”导航已经接入专用环境台账页面。
2. 当前页面使用 React、TypeScript、Ant Design 和 TanStack Query。
3. 服务端为 Node.js 兼容网关，业务数据使用本机 PostgreSQL。
4. 组织机构已经使用隐藏物理 ID 作为主键，业务 Code 保持唯一。
5. 当前组织机构共有 105 条，页面已经具备全局组织机构选择器。
6. 环境组、环境、产品、版本、功能模块、连接端点和环境产品关系已经建立数据库表、接口与前端类型。
7. HTTPS 首页已经接入用户认证与角色权限。环境凭据使用独立权限、加密存储和显式查看审计。

### 3.2 EnvPortal 可复用经验

旧项目已经形成以下业务经验。

1. 使用“组织机构、环境组、环境”三层结构。

3. 一个环境可以关联多台 AP、DB、跳板机或其他服务器。
4. 环境组支持新增、改名、排序、移动和空组删除。
5. 环境支持新增、编辑、复制、移动和删除。
6. 生产环境页面通过环境用途筛选形成。
7. 旧项目设计文档已经提出社内、本番、生产、开发、测试和受入等维度。

旧项目当前工作区中的实际运行文件仍是早期格式。

## 4. 页面总体设计

### 4.1 客户隔离

1. 环境页面继续使用 OneOps 顶部的组织机构选择器。
2. 所有查询和写入都使用组织机构物理 ID。
3. 页面首次进入时只加载当前组织机构的环境。
4. 普通用户不提供“全部客户”视图。
5. 具有跨组织调查权限的用户可以使用专门的高级搜索，搜索结果必须显示客户名称并记录审计。
6. 切换客户时清空当前选择、筛选条件、未保存草稿和已显示的秘密信息。

### 4.2 页面结构

桌面版采用三栏主从结构。

1. 顶部概要区

   1. 显示客户名称。
   2. 显示生产、检证、社内、退役环境数量。
   3. 显示待审核资料、冲突事实、长期未确认信息数量。
   4. 提供“新增环境”“管理分组”“导入资料”三个主要操作。

2. 左侧环境组导航

   1. 显示环境组及环境数量。
   2. 支持新增、改名、排序和归档。
   3. 只允许归档空组。
   4. 提供“全部环境”“生产”“检证”“社内”“已退役”固定入口。

3. 中间环境列表

   1. 每行显示环境名称、范围、用途、状态、产品版本、VPN 状态和最后确认日期。
   2. 使用紧凑列表承载大量环境，避免旧项目大卡片造成的纵向空间浪费。
   3. 支持按名称、用途、状态、产品、版本、VPN 状态和确认状态筛选。
   4. 默认排序为环境组顺序、环境顺序、环境名称。
   5. 风险提示只表达可核实状态，例如“存在冲突”“缺少来源”“超过确认期限”。

4. 右侧环境详情

   1. “基本信息”页签显示名称、范围、用途、状态、URL、备注和负责人。
   2. “产品与版本”页签显示产品、版本、使用状态和用途。
   3. “服务器与连接”页签显示并维护 AP、DB、跳板机和其他端点，同时提供凭据登记、显式查看和复制。
   4. “VPN”页签显示 VPN 配置、接入条件、账号引用和操作手顺。
   5. “资料与依据”页签显示来源文件、证据位置、冲突和确认状态。
   6. “变更履历”页签显示新增、编辑、审核、归档和秘密查看记录。

小屏幕下保留环境列表，详情改为全屏抽屉。环境维护业务以桌面版为主要验收对象。

### 4.3 新增与编辑

新增环境使用分步抽屉。

1. 选择环境组、范围、用途和状态。
2. 输入环境名称、URL、负责人和备注。
3. 选择产品及版本。
4. 登记服务器、数据库和 VPN 关系。
5. 显示保存摘要并提交。

编辑使用同一数据结构。保存时提交当前记录修订号。服务端发现修订号落后时拒绝覆盖，并返回最新数据供用户比较。

环境删除统一采用归档。

1. 归档前显示关联产品、端点、VPN 和未完成审核数量。
2. 归档记录从默认列表隐藏。
3. 有权限的用户可以恢复归档记录。
4. 普通业务操作不提供物理删除。

### 4.4 环境组

1. 环境组属于单一组织机构。
2. 组名在同一组织机构内唯一。
3. 组顺序使用明确的整数排序字段。
4. 环境移动到其他组时只修改组物理 ID。
5. 环境组不能跨客户移动。
6. 需要跨客户复用时使用“复制为新环境”，复制结果必须重新确认产品、VPN 和秘密信息。

### 4.5 产品、版数与功能模块档案层级

1. 产品、版数与功能模块属于系统共通基础档案，不属于任何组织机构。
2. 三级档案在“管理”的基础档案目录中，与组织区分处于同一层级。
3. 基础档案目录只设置一个“产品与版数”入口。
4. 产品是主档，版数是所选产品的子档，功能模块是所选版数的孙档。
5. 版数通过产品物理 ID 归属于一个产品。稳定功能模块属于产品，模块在各版数下形成可选版本实现。
6. 产品、版数和功能模块在同一画面展示与维护，不拆分为多个基础档案入口。
7. 环境先引用产品版数，再从该版数下选择实际采购的功能模块。
8. 服务端拒绝把其他版数的功能模块关联到当前环境产品版数。
9. 每个组织机构的环境引用共通档案物理 ID，不复制产品、版数或功能模块记录。
10. 切换组织机构不会改变产品、版数与功能模块档案内容。

## 5. 数据模型

所有表使用独立物理 ID。所有强关联使用物理外键。

### 5.1 环境核心

1. `environment_groups`

   保存组织机构 ID、组名、排序、归档时间、创建人与更新时间。

2. `environments`

   保存组织机构 ID、环境组 ID、名称、范围、用途、状态、URL、负责人、备注、排序、修订号、最后确认时间和归档时间。

3. `environment_endpoints`

   保存环境 ID、端点名称、角色、主机名、IP、端口、协议、操作系统、数据库类型、数据库版本、连接说明和秘密引用。

端点角色至少支持 AP、DB、跳板机、负载均衡、文件服务器和其他。

### 5.2 产品与版本

1. `products`

   保存系统共通的产品 Code、正式名称、简称、分类、生命周期状态和排序。该表不保存组织机构 ID。

2. `product_versions`

   保存产品 ID、标准版本、显示版本、生命周期状态和备注。产品 ID 是版数所属主档的强关联。

3. `environment_product_versions`

   保存环境 ID、产品版本 ID、使用状态、用途、确认状态、最后确认时间和备注。

4. `product_modules` 与 `product_version_modules`

   `product_modules` 保存产品下稳定的模块身份。`product_version_modules` 保存该模块在具体产品版数下的名称、状态和排序。

5. `environment_product_version_modules`

   保存环境 ID、产品版数 ID 和功能模块 ID。复合外键保证环境已经引用该版数，并保证模块属于同一个版数。

6. `organization_product_candidates`

   保存机构 Excel 等来源生成的客户级产品候选、原始值、来源位置和审核状态。

产品版本必须绑定具体产品，功能模块必须绑定具体产品版本。客户级 V6 或 V7 只能作为候选提示，不能替代环境级产品版本或已采购功能模块。

### 5.3 VPN

1. `vpn_connections`

   保存组织机构 ID、VPN 名称、供应商或产品、网关地址、连接方式、客户端版本、认证方式、MFA 要求、证书要求、来源 IP 限制、可连接时间、账号申请方法、密码重置方法、维护联系人、操作手顺、状态和最后确认时间。

2. `environment_vpn_connections`

   保存环境 ID 与 VPN 连接 ID。一个 VPN 可以服务同一客户的多个环境，一个环境也可以有多个 VPN 接入方式。

3. VPN 用户名、密码、证书私钥和一次性密码种子只保存秘密引用。

### 5.4 资料、候选事实与审计

1. `environment_documents`

   保存组织机构 ID、文件名、文件类型、文件哈希、文件日期、上传人、来源系统、解析状态和保密等级。

2. `environment_fact_candidates`

   保存候选事实类型、目标记录、目标字段、原始值、标准化值、有效期间、置信度、冲突组、审核状态和生成任务 ID。

3. `environment_fact_evidence`

   保存候选事实 ID、资料 ID、页码、工作表、单元格、段落、短证据摘要和来源日期。

4. `environment_audit_events`

   保存操作者、组织机构、对象、动作、变更前摘要、变更后摘要、时间和请求关联 ID。

5. `secret_records`

   只保存加密秘密、秘密类型、使用范围、轮换时间和访问策略。普通查询永远不返回加密内容。

6. `environment_endpoint_credentials`

   以端点物理 ID 为主键保存 AES-256-GCM 加密载荷、用户名与密码登记状态、来源系统和修订号。环境清单只返回登记状态，显式查看接口在权限检查和审计后返回明文。

## 6. VPN 资料的 AI 治理流程

AI 能力属于后续阶段。本规划不要求现在创建 API 密钥。

### 6.1 处理流程

1. 上传与归属

   文件上传时必须先选择客户。系统计算哈希，识别完全重复文件，并保留原文件元数据。

2. 本地解析

   先在本机提取 PDF、Word、Excel、PowerPoint、文本和图片内容。扫描件使用 OCR。加密文件和无法解析文件进入人工处理队列。

3. 敏感信息处理

   在调用外部 AI 前，本地识别密码、私钥、令牌、一次性密码种子和个人信息。秘密值使用占位符替换，原值留在本机受控区域。

4. 候选提取

   AI 只输出符合固定结构的候选事实，包含字段、值、适用环境、有效日期、来源位置、置信度和判断说明。

5. 冲突检测

   系统比较同一客户、同一环境和同一字段的候选。不同值、不同有效期和不同资料日期形成冲突组。

6. 人工审核

   审核人可以接受、修改后接受、合并、拒绝或标记为过时。任何置信度都不能直接跳过审核。

7. 发布

   接受候选后，系统生成正式环境变更并增加修订号。原候选、证据和审核记录继续保留。

### 6.2 来源判断规则

系统可以给出排序建议，最终结论由审核人确认。

1. 明确写有修正、勘误、废止或替代关系的资料优先展示。
2. 在适用日期相同的情况下，更新日期较新的资料优先展示。
3. 客户正式通知、正式手顺和签章资料的建议权重高于个人备忘。
4. 已经人工确认的正式事实不会被新候选静默覆盖。
5. 缺少日期、作者或适用环境的资料自动标记为依据不足。
6. AI 提取的值必须携带可定位证据。缺少页码、单元格或段落位置的候选不能发布。

### 6.3 审核队列

审核队列按客户隔离，并提供以下分类。

1. 新发现事实。
2. 与正式台账冲突。
3. 多份资料互相冲突。
4. 可能已经过时。
5. 缺少适用环境。
6. 缺少产品或版本映射。
7. 包含秘密信息，需要安全处理。
8. 无法解析，需要人工录入。

## 7. 权限与秘密信息

OneOps 已有用户认证、角色授权、组织机构范围检查和认证审计。

1. `environment_view`：查看普通环境信息。
2. `environment_edit`：新增和编辑环境。
3. `environment_archive`：归档与恢复环境。
4. `environment_secret_view`：按次查看秘密。
5. `environment_document_upload`：上传来源资料。
6. `environment_fact_review`：审核候选事实。
7. `environment_master_manage`：维护产品与版本档案。
8. `environment_cross_organization_search`：跨客户调查。

权限必须同时检查功能权限与组织机构范围。

画面とインターフェースの権限境界を一致させる。`environments.read` は環境台帳の参照に限定し、`environments.write` は環境、環境グループ、接続端点の追加、編集、並べ替え、アーカイブを制御する。環境資格情報は `environments.credentials.read` と `environments.credentials.write` を分離し、参照権限がない場合は明文資格情報を取得せず、更新権限がない場合は保存操作を表示しない。製品バージョン選択は環境更新権限と `catalog.read` の両方がある場合に限って製品台帳を取得する。ログイン中に権限が変更された場合は、無効になった編集画面を閉じ、制限対象のクエリーキャッシュを削除する。

秘密信息遵循以下规则。

1. 列表和普通详情只显示是否已登记。
2. 查看秘密需要单独操作，并记录操作者、客户、环境、字段和时间。
3. 复制秘密到剪贴板同样记录审计。
4. API 响应、日志、错误信息、AI 输入和前端缓存不得包含未遮罩秘密。
5. EnvPortal 明文凭据仅在导入进程内读取，进入 OneOps 前完成加密。暂存行、报告、日志和普通环境接口均不保存或返回明文。

## 8. 接口与前端类型

接口继续使用现有前缀 `/api/work-center/v1`。

### 8.1 主要查询

1. `GET /organizations/{organizationId}/environment-inventory`

   返回当前客户的环境组、环境摘要、筛选档案和审核数量。

2. `GET /environments/{environmentId}`

   返回环境详情、产品版本、端点、VPN 关系、证据摘要和修订号。

3. `GET /products`
