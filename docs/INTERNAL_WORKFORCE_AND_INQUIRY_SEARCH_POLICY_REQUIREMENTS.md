# 社内部門・業務職責・問合検索既定方針 要件

更新日: 2026-08-04

## 目的

OneOps の既存利用者及び RBAC ロールを維持したまま、社内の所属情報、業務上の担当分類、問合支援の検索テンプレート及び既定適用方針を追加する。

## 境界

1. `organizations` は顧客、機関等の業務組織を表す。社内所属には使用しない。
2. `internal_departments` は社内人員組織を表し、親部門の物理 ID による階層を持つ。
3. `business_responsibilities` は導入、技術、支援、管理等の業務分類を表す。権限集合は既存 RBAC ロールが引き続き担う。
4. 利用者、部門、職責、ロール、検索テンプレートの強参照は物理 ID と外部キーを使用する。Code と名称は表示及び検索用とする。
5. 第一版の所属情報は OneOps 管理者が登録する。Windows SSO の部門属性は自動更新に使用せず、将来の写像及び承認付き同期候補とする。

## データ

### 社内部門

`internal_departments` は物理 ID、Code、名称、親部門 ID、有効状態、表示順を持つ。`user_department_memberships` は利用者 ID、部門 ID、主所属、有効開始日、有効終了日を持つ。一人の利用者に同時点で有効な主所属は一件だけとする。

### 業務職責

`business_responsibilities` は物理 ID、Code、名称、説明、有効状態を持つ。初期値は `INTRODUCTION`、`TECHNICAL`、`SUPPORT`、`MANAGEMENT` とする。

`user_responsibility_assignments` は利用者 ID、部門 ID、職責 ID、主職責を持つ。職責と RBAC ロールの自動写像は今回の受入範囲外とし、必要な権限は既存ロール割当で管理する。

### 問合検索テンプレート

`inquiry_search_templates` は物理 ID、Code、名称、説明、検索条件 JSON、初回自動実行、有効状態、Revision、作成者及び更新者を持つ。検索条件は問合支援 API が受け付ける項目だけを保存する。

担当者条件は実サイトへ送る `value` と表示名称を同時に保存する。実サイトの選択肢に `value` が存在しない場合はテンプレートを失効扱いとして画面へ表示し、担当者条件を外した検索は実行しない。`TODAY` は利用時に OneOps のシステム時区で当日へ変換する。

## 既定方針

テンプレートの対象は `SYSTEM`、`DEPARTMENT`、`RESPONSIBILITY`、`ROLE`、`USER` の五種類とする。優先順位は整数で管理し、大きい値を優先する。

既定テンプレートは次の順で解決する。

1. 利用者が画面で使用中の検索状態
2. 利用者
3. 主所属部門における業務職責
4. 主所属部門
5. RBAC ロール
6. システム

同じ解決段階で最大優先順位の有効な割当が複数ある場合は設定不整合とする。条件を合成せず、管理者向け識別情報を含む設定エラーを返す。

## 管理画面

システム管理に次の子機能を設ける。

1. ユーザー管理
2. 業務部門・職責
3. ロール・権限
4. 問合検索テンプレート

ユーザー管理では主所属、兼務所属及び部門別職責を編集する。通常利用者のプロフィールではこれらを参照専用で表示する。業務部門・職責では部門階層と職責台帳を管理する。問合検索テンプレートではテンプレート、対象、優先順位及び有効状態を管理する。

## 問合支援の動作

1. 画面に保存済みの検索状態がある場合はその状態を復元する。
2. 保存済み状態がない場合はサービス側で現在利用者の有効テンプレートを解決する。
3. 実サイトの担当者等の選択肢を取得し、テンプレート内の実値を検証する。
4. 有効なテンプレートをフォームへ反映し、`autoExecute` が有効なら一回検索する。
5. 適用元を画面に表示する。
6. 利用者の一時変更を保存し、画面再訪、ブラウザー履歴、更新及び詳細 Drawer からの復帰で維持する。
7. 「既定に戻す」は保存済み状態を破棄し、その時点の有効テンプレートを再解決して適用する。

## 権限

`identity.workforce.read` と `identity.workforce.write` は社内部門及び職責台帳を制御する。`inquiries.templates.read` と `inquiries.templates.write` は検索テンプレート及び割当を制御する。`SYSTEM_ADMIN` には全てを付与する。問合支援の利用自体は既存 `inquiries.use` を維持する。

## 受入条件

1. 物理 ID と外部キーで全ての強参照が保持される。
2. TS2 課、四種類の初期職責、利用者の複数所属及び部門別職責を登録できる。
3. 五種類の対象を持つテンプレート割当を登録できる。
4. 解決順、同順位エラー、`TODAY`、担当者実値不一致を自動試験で確認できる。
5. 問合支援で既定の適用元、復元、再適用及び初回自動検索をブラウザーで確認できる。
6. 関連する Backend、Portal、Gateway の試験、ビルド、正式画面、Console 及び Screenshot を確認できる。
